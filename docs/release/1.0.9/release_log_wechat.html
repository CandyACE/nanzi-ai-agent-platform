项目声明

本项目为个人开源，供自由学习交流，遵循 MIT 开源协议，可自由分发。

「NanZi」取自我常用的网名「南孜」，寓「孜孜不倦」——持续学习与打磨。

GitHub： RandyChen1985/nanzi-ai-agent-platform

v1.0.9 的首要能力，是支持 PostgreSQL 作为平台智能体元数据库（主库）。此前平台元数据（系统配置、角色权限、审计日志、智能体与版本等）主要落在 MySQL；本版通过 DATABASE_TYPE=postgresql 与独立脚本目录 db-prod-pg/，可与 MySQL 双引擎任选其一，互不混用。

在此之上，本版继续推进 MCP 个人作用域与工具可用性、案例集/经验库检索、模型注册表治理与运行时身份透明、知识库与 Embed 交互、危险 Shell 护栏与事实取证分级。远端已删除的 MCP 工具会标记不可用但仍保留可见；新增 search_qa_examples / get_myinfo；记忆统一全局向量模型（默认 bge-m3 / 1024）；并修掉一批管理台抖动、发布权限与流式图表对账问题。

WHAT'S NEW

主要更新

01 · PostgreSQL 作为平台智能体元数据库

这是本版最重要的基础设施能力：平台主库不再只能选 MySQL，智能体与系统元数据可完整运行在 PostgreSQL 上。

双主库可选：通过 DATABASE_TYPE=mysql|postgresql 切换；不配置时默认仍为 MySQL。

元数据落库：系统配置、角色权限、审计日志、智能体/版本/工具与会话等平台元数据均可落在 PG。

独立脚本链：新增 db-prod-pg/（V0 当前态基线 + 后续增量），与 MySQL 的 db-prod/ 并行维护，互不改写、不可混跑同一实例。

运行时方言：SQLAlchemy / APScheduler 与 upsert、分区维护等按主库类型分支；审计相关服务同步加固。

安装运维：HOW_TO_INSTALL / Docker / env.example 补齐 POSTGRES_*；MySQL / PG 的 apply-sql 均支持相对路径解析。

02 · MCP 作用域、可用性与管理体验

MCP 从「只能公共接入」走向更清晰的作用域与生命周期治理，减少禁用误同步、远端工具静默消失等问题。

个人作用域：服务支持 global / personal 与创建者隔离；完善重命名迁移与权限校验。

显示名唯一：强制服务显示名全局唯一（大小写不敏感）；历史重名自动追加 legacy-* 标记，避免工具标识冲突。

远端可用性：远端已删除工具标记 is_available=false 且保留可见；与「是否发布给智能体使用」解耦。

管理台：展示服务绑定智能体；修复禁用后误同步与发布状态生效；美化工具测试台结果与启停加载态。

探测与权限：优化 SSE/HTTP 探测与欢迎语文案；修复普通用户发布 MCP 工具权限；更新 Skills 官方市场链接。

03 · 案例集 / 经验库与内置工具

让「已经验证过的问答与 SQL 口径」可被智能体主动检索复用，同时补齐本人资料一类高频意图。

案例集通用化：案例集管理全面优化与重构，支持分类（general / knowledge / data_query）。

search_qa_examples：新增内置工具检索经验库，参考同类指标的计算口径或表关联方式。

get_myinfo：新增本人资料查询工具，并优先处理「我的信息」类意图，减少绕路调用。

04 · 模型注册表、运行时身份与向量模型

模型侧更强调「选得准、用得清、配得稳」：唯一性约束、限额字段、使用关系与本轮实际生效模型都可查。

注册表治理：强化安全与供应商接入；完善解析、管理台筛选与高级设置交互。

唯一性与限额：model_id 全局唯一；支持可选 context_size / max_output_tokens（空值保持供应商默认）。

使用关系：完善模型被哪些智能体/能力引用的展示，并消除管理页抖动。

运行时身份：支持查询本轮实际生效的运行时模型身份，便于排障与对账。

全局 Embedding：记忆与系统配置统一使用全局向量模型；默认调整为 bge-m3、维度 1024。若旧记忆索引基于其他维度，升级后需按运维指引评估重建。

05 · 知识库智能体与 EmbedChat 体验

面向知识库配置与嵌入式聊天，减少「看不懂工具步、等得慌、手机表格难读」这类体验摩擦。

工具步：知识库工具步增加绑定引导；默认折叠 ChatBI；支持隐藏 AI 消息外框，界面更干净。

调度占位：Embed 思考中显示调度占位（三点跳动 + 名称淡入上滑）；优化无边框消息样式；淡化思考时间轴竖线。

移动端表格：Markdown 表格可自适应在「卡片 / 表格」间切换；多主题表格样式一并优化。

技能计数：智能体卡片技能数展示启用公共技能总量，统计更符合实际可用能力。

06 · 安全、取证与 AI 契约

把「别误删、别乱编、图表别截断」写成可执行护栏，而不是事后补救。

危险 Shell 护栏：拦截危险删除类 Shell 操作，降低误删风险。

取证分级：全局事实取证风险提示按凭证重合度分级，让用户更清楚「依据有多扎实」。

检索与路由：优化知识库检索触发，与单轮意图解耦，减少误触发；事实证据契约与路由冲突治理。

图表契约：统一 ECharts 输出契约，修复 quick 括号截断；流式对账支持嵌套括号，避免半截图表。

07 · 运维与体验加固

记忆索引：索引未就绪时提供快捷创建入口，减少卡在半配置状态。

AI 润色权限：智能体版本编辑器 AI 润色不再依赖提示词工坊权限，降低协作门槛。

08 · 缺陷修复

MCP / 运维：普通用户发布 MCP 权限；禁用后误同步；MySQL/PG apply-sql 相对路径；规范 MCP 默认服务名。

AI / ChatBI / 知识库：工具步校验与审计日志截断；知识库检索误触发；证据契约与路由冲突；ECharts/流式嵌套括号；打开已保存报告时关闭浏览器浮层。

前端 / Embed：鼠标悬停滚动条抖动；模型管理页抖动；多智能体开关重复 Toast；模型表单多余「可选」文案；注册表高级设置与选择器交互。

MIGRATION

升级注意

从 v1.0.8 升级至 v1.0.9 时，请特别关注以下变更：

项目 说明
PostgreSQL 主库 新增 DATABASE_TYPE=postgresql 与 POSTGRES_*；智能体元数据可落 PG。MySQL 与 PG 两套脚本链并行，不可混用同一库。
MySQL 存量 继续使用 MySQL 时，须执行 db-prod/ 的 V105 ~ V111。
PostgreSQL 新装 新环境执行 db-prod-pg/ 基线（V0 起）；已有 PG 环境执行对应增量（本版对齐能力见 V3 ~ V9）。
MCP 作用域 / 命名 新增 scope / user_id；显示名全局唯一。历史重名会追加 legacy-*，请核对接绑定配置。
MCP 可用性 远端已删除工具不再静默消失，而以不可用状态保留；发布态与可用性分离。
model_id 唯一 强制全局唯一；存在重复时迁移会失败，须先手工清理。
Embedding 默认 记忆默认改为 bge-m3 / 1024 维；旧维度索引可能需重建。

DATABASE

数据库增量

MySQL 存量升级执行 V105~V111（共 7 个）； PostgreSQL 新装走 db-prod-pg/（V0 基线 + V3~V9 对齐本版能力）。勿对同一实例混跑两套目录。

MySQL（db-prod/）

脚本 内容
V105 MCP 增加 scope / user_id；注册 MCP 管理菜单权限。
V106 案例表增加 category 分类列。
V107 注册内置工具 search_qa_examples。
V108 MCP 显示名全局唯一；历史重名追加 legacy-*。
V109 MCP 工具缓存增加 is_available（远端是否仍存在）。
V110 ai_models.model_id 全局唯一（重复须先清理）。
V111 可选 context_size / max_output_tokens。

PostgreSQL（db-prod-pg/）

脚本 内容
V0 平台当前态全量基线（智能体元数据等）。
V3 ~ V9 与 MySQL V105~V111 能力对齐：MCP 作用域/唯一性/可用性、案例分类、经验检索、model_id 唯一与 Token 限额等。

UPGRADE

升级步骤

# 继续 MySQL 主库

git pull && pip install -r requirements.txt

./db-prod/apply-sql-native.sh # V105~V111

cd frontend && npm i && npm run build

# 新装 / 切换 PostgreSQL 主库

DATABASE_TYPE=postgresql # 并配置 POSTGRES_*

./db-prod-pg/apply-sql.sh
