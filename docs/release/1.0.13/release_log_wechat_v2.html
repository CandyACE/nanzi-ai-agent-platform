🚀 核心更新亮点 (Key Features)

1. 🔁 统一可复用结果链路与跨轮分析引用

  • 结果先整理，再决定能不能继续用：通过 build_reusable_result 等统一处理方式，把数据查询、工具或知识库得到的结果整理成可继续使用的结果；系统会先检查结果是否有实际内容、是否失败、过期，或是否必须重新获取最新数据。
  • 下一轮对话可以接着问：通过 resolve_reusable_result 判断怎么处理：有合适的当前结果就直接使用，当前结果不合适时再找最近的历史结果；如果用户明确要求最新数据、结果不存在或类型不匹配，就重新查询。本次确实使用了旧结果时，页面会明确标记出来。
  • 当前结果和最近结果都能找回：MemoryService 会保存当前结果和最近的历史结果，最多保留 10 条，并自动去掉重复项；结果按用户和会话分开保存，避免不同用户或不同对话互相串用。

简单说：AI 会把查询、工具和知识库返回的有效结果整理好，并先检查结果是否为空、失败、过期，或必须重新获取。这样上一轮查到的华东销售额，下一轮就可以直接要求和华南比较，不用从头再查。

2. 💬 聊天消息持久化重建、幂等门控与取消恢复

  • 后台持久化与一致性：优化聊天消息与记忆后台持久化，修复取消与历史恢复不一致、浏览器会话状态同步错位。
  • 幂等防重复上送：基于 client_request_id 幂等校验与去重，前端 useChatSendGate 发送门控杜绝重复发送。
  • 运行状态心跳与统一错误：error_response_service 统一错误分类，新增 ErrorDetailCard.vue 流式错误详情卡片与运行状态轮询。
  • 正文完整性守护：修复任务清单更新吞掉最终正文、处理 todo_write 后正文丢失等边界问题，移动端收纳数据文件入口。

简单说：消息、思考过程和分析结果会更稳地保存下来。即使重复点击发送、途中取消任务，或稍后重新打开历史会话，也能减少重复任务、正文丢失和前后内容对不上的情况。

3. 🧹 上下文手动压缩与比例控制

  • 手动压缩引擎：支持手动触发上下文压缩并控制压缩比例，与既有自动溢出压缩形成「自动 + 手动」双引擎。
  • 记录卡片与文案优化：优化压缩记录卡片布局，精简智能压缩提示文案。
  • 能力发现与会话聚焦：完善运行时能力发现与会话聚焦，让模型与面板聚焦当前会话所需能力。

简单说：对话变长后，可以自己选择压缩比例，把前面的重点整理出来再继续对话；系统也会在内容过长时自动压缩。比如长时间分析一个项目时，不必因为对话太长而重新开始。

4. 🛡️ 会话身份「Fail-Closed」隔离、全量工具透传与思考协议自适配

  • 严格身份隔离（Fail-Closed）：彻底废除 anonymous 降级，会话存储、Redis 键、工作区、审计全链路绑定真实 user_id，杜绝多租户越权。
  • 全量工具透传：废弃当前轮关键词动态裁剪门禁，系统隐式 + 配置 + MCP 工具全量透传，保持原生多轮消息流。
  • 思考协议自适配：原生支持 DeepSeek V4、Kimi、智谱、火山引擎、DashScope、SiliconFlow 等思考协议，兼容强制 tool_choice 参数冲突并优雅降级。
  • 降级可见通知：主模型失败触发 Fallback 时推送 model_fallback 结构化事件。

简单说：多人共用平台时，每个人的会话、文件和工作区都会严格分开；身份无法确认时，系统宁可不继续操作，也不会随意放行。主模型遇到问题时，还会明确提示已切换备用模型。

5. 🐳 Docker 沙箱交互式终端、公共文档隔离与预构建流式日志

  • 交互式终端：新增 stop / restart / exec 端点，支持停止容器、强制删除重建与容器内交互执行；前端 DockerTerminalModal 支持历史命令翻阅、快捷命令、一键清屏与复制。
  • 中文欢迎卡：每次打开渲染含容器 ID、工作目录、资源限制与生命周期边界的彩色欢迎卡。
  • 公共 docs 只读挂载：公共文档只读挂载至 /workspace/public/docs，个人技能目录隔离。
  • 预构建流式日志：/prebuild-stream SSE 端点实时推送构建日志与进度条，镜像优先阿里云加速源。

简单说：管理员可以像打开一个安全的临时工作台一样，在页面里执行命令、查看文件和观察构建进度。公共文档只能查看，个人技能目录单独隔离，减少误改和相互影响。

6. 🌐 8 大企业级浏览器工具、验证码自解算与人机协同

  • 8 大高级浏览器工具：全局拟人化交互引擎、智能元素高亮检视、自适应低带宽压缩、远程页面滚动快照同步。
  • 验证码自解算与人工兜底：基于多模态大模型自动解算验证码，失败时无缝切换人工协同。
  • 单击选定 + 双击执行：单击高亮元素轮廓展示 [#ref] 语义标签，双击确认执行，防止远程串流误触。
  • 缓存占用可视化：浏览器面板与个人中心展示云端缓存磁盘占用与一键清除，两次点击确认清理。

简单说：浏览器会先把准备操作的按钮或输入框标出来，单击选中后，双击才真正执行；遇到验证码或复杂页面，也可以交给人工接管。这样更适合登录、填表、查询等不能随便误点的场景。

7. 🧭 六大业务中心全生命周期引导与规范大弹窗

  • 智能体中心：梳理 定义 / 装配 / 版本发布 / 角色授权 / 调试消费 5 步流程，帮助弹窗明确系统自动路由与 Readiness 校验标准。
  • 知识库 / MCP / 任务 / 案例集：分别落地环境连通、连接协议与 Scope 权限、Cron 编排与审批、会话点赞沉淀闭环等指引。
  • 技能 / 提示词 / 数据源 / 记忆工作台：新增 SkillFlowGuideBanner 与 帮助规范弹窗，覆盖研发 5 步流、多源连接与 Redis Stack 向量索引。
  • 统一折叠交互：指引横幅「默认折叠」，Header 统一放置 帮助规范弹窗按钮与恢复入口。

简单说：新用户进入智能体、知识库、任务或数据源页面后，都能看到从准备到测试的操作顺序。可以先照着做，熟悉后再把指引收起来，不用一开始就理解所有配置。

8. 📊 数据门户固化报表工作台重构与智能发现双视图

  • 固化报表工作台：抽屉顶部双 Tab + 主页左侧垂直导航；手工开发新建报表支持选源、手写 / 粘贴 SQL、试跑测试、前 50 条预览与一键固化入库。

  • AI 保存报表上下文继承：自动继承本轮 data_source 与 dataset_id，避免回退默认源。
  • 智能指标 / 实体关系双视图：支持按需选表、折叠、秒表计时与双视图 ER 图，报表列表视图与推荐指标详情弹窗。

简单说：做报表时可以先选择数据、试跑查询并查看前 50 条结果，确认无误后再保存。比如先确认“本月各地区订单量”正确，再保存成固化报表，之后直接打开就能继续使用。

9. 🧰 工具调用超时治理、权限卡片与执行时间线优化

  • 超时与次数上限：新增全局 agent_max_toolcall_timeout（默认 120s）与版本级 toolcall_timeout_seconds；新增 agent_tool_loop_global_limit（默认 50）防工具空转。
  • 权限卡片与时间线：新增 ToolPermissionCard 组件，执行时间线优化阶段卡片渲染与动画。
  • Shell 删除策略增强：识别 Python / Node 脚本内删除调用，补充资源目录统计上报。

简单说：每次工具操作都有最长等待时间，一轮对话也有最多调用次数，遇到异常时还能看到更具体的权限和执行步骤。这样可以避免任务一直卡住或在后台反复尝试。

10. ⏳ 会话排队透明化与路由大模型超时保护

  • 并发排队状态透传：ConversationRunLane 新增 is_locked 探测，上一轮未完成时 SSE 实时下发「等待上一次会话任务完成」进度日志。
  • 路由大模型超时保护：为未指定智能体时的路由调用添加 15s 有界超时，超时重试后平滑回退兜底助手。
  • 思考定时器优化：优先保持后端推送的活跃 pending 步骤文案，为排队状态添加专属沙漏图标。

简单说：上一项任务还没结束时，页面会明确告诉你正在等待，而不是看起来像卡死；如果系统判断该选哪个助手时超时，也会在保护时间内切换到备用助手。

📦 快速升级指南 (Upgrade Guide)

💡 如果你只是使用已经部署好的 NanZi，可以跳过本节；本节供负责源码或 Docker 升级的管理员参考。

⚠️ 升级前置提醒：无论采用源码还是 Docker 升级，请务必先备份数据库，并在服务启动前执行数据库升级脚本！

方式一：源码直接升级（本地 / 虚机部署）

# 1. 拉取最新代码

git fetch origin && git checkout main && git pull origin main

# 2. 执行数据库升级 (V130~V134)

./db-prod/apply-sql-native.sh # PG: ./db-prod-pg/apply-sql.sh

# 3. 启动服务（dev.sh 自动准备 uv/Python3.11 环境、按需安装前后端依赖）

./dev.sh # 后台启动: ./dev.sh -d

方式二：Docker 容器化升级（生产环境 / 容器集群）

场景 A：从 Release 下载镜像离线加载（推荐）

# 1. 下载并加载镜像归档（按架构选择）

docker load -i nanzi-ai-agent_1.0.13.0_linux-amd64_*.tar # ARM: arm64_*.tar

# 2. 执行数据库升级

./db-prod/apply-sql-native.sh # PG: ./db-prod-pg/apply-sql.sh

# 3. 启动 / 重启容器

cd docker && ./start-nanzi-ai-agent.sh

场景 B：本地 / 服务器自主构建镜像

# 1. 拉取最新代码并执行数据库迁移

git pull origin main && ./db-prod/apply-sql-native.sh

# 2. 构建 v1.0.13.0 镜像并重启

cd docker && ./build_linux_x86.sh 1.0.13.0 # ARM: ./build_linux_arm.sh 1.0.13.0

./start-nanzi-ai-agent.sh
