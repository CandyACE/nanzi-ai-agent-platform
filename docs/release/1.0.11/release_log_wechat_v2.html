NanZi 开源智能体平台正式发布 v1.0.11 版本！本次迭代以 AgentScope 2.0.6 深度升级与通用业务数据确认卡（Human-in-the-Loop） 为核心领衔，并全面推进 双重路由优化与意图识别合并、非多模态模型图片旁路解析、思考卡过程话术入卡与时间线历史回放、Embed Ticket 临时嵌入凭证体系与 24h 滑动续期、ChatBI 明细/依据/引用多维交互与健壮性收口，以及工作空间与任务中心体验优化。

本次变更自 89e88d49 至 2c8a3fbf，共 53 个提交（45 个非 Merge 提交），变更 229 个文件。

🚀 核心更新亮点 (Key Features)

1. 🤖 AgentScope 2.0.6 深度集成与内核优势

  • 原生结构化输出（Structured Output）：深度接入严格 JSON Schema 约束生成，替代松散正则提取，使 ChatBI 语义意图解析与多轮状态分类的解析准确率提升至接近 100%。
  • 洋葱圈架构中间件（Onion-chain Middleware）：利用 2.0.6 中间件钩子系统（extra_agent_middlewares），实现权限预检拦截与 Token 统计无侵入挂载，强化智能体执行安全与审计。
  • 流式聚合与 ReAct 轮次治理：以片段聚合（Fragment Joining）替代高频字符串拼接，彻底修复工具并发状态重置与推理轮次计数偏差，提升高并发流式输出稳定性。
  • 运行时状态注入（InjectionConfig）：新增系统配置 agentscope_inject_runtime_state 与 agentscope_inject_time_interval_hours，支持按需注入时间与上下文占用，时区跟随 platform_timezone。
  • 会话事实工具与思考调优：新增平台只读 session_status 工具；关闭思考时显式传递 false，全面对齐厂商思考参数下发协议。

2. ⏱️ 思考卡演进：过程话术入卡与时间线历史回放

  • 过程话术入卡：模型在执行过程中的规划、反思、过渡语与工具步骤统一归入折叠思考卡，保持主消息正文纯净清爽。
  • 思考时间线快照：执行历史表增加 process_timeline JSON 快照字段，刷新页面或加载历史会话时可完整回放思考卡与步骤时间线。
  • 真实生成中断：点击「停止」按钮真正向后端下发任务取消信号，立即终止 LLM 推理与工具执行。

📷

3. 🎫 Embed Ticket 临时嵌入凭证与 24h 滑动续期

  • 临时凭证体系：新增 Embed Ticket 临时嵌入凭证体系与服务端代客签发接口，支持白名单域名校验与权限隔离。
  • 兼容性与生产推荐：原有的静态 Token 验证集成方式兼容保留，现有对接代码无需改动；生产环境强烈推荐使用安全性更高的 Embed Ticket 代客签发方式。
  • 滑动续期机制：Session Token 滑动续期调整为 24 小时，保障长效嵌入会话的平滑交互体验。
  • 调试台升级：组件调试台支持 strict_token 严格校验模式与 Token 必填校验，升级嵌入集成指南。
  • 移动端对齐：修复移动端 AIChat 横向溢出问题，对齐 EmbedChat 上行事件协议与会话数据隔离。

📷

【示例截图占位】：Embed Ticket 代客签发、Widget 调试台与严格校验模式展示

4. 📋 通用业务数据确认卡与人机协同治理

  • 通用确认工具：新增平台通用只读确认工具 request_user_confirmation 与 SSE 事件出卡机制。
  • 可交互编辑卡片：前端在 AI 消息正文下方渲染可交互确认卡片，支持用户直接修改关键业务字段并点击「确认执行」或「取消」。
  • 模型驱动回传：操作结果以【业务确认】+ 字段快照消息结构化回传模型继续驱动执行，与底层工具执行确认（Tool Approval）清晰解耦。
  • 防重复与硬拦截：有确认卡时自动收起 quick 引导；用户取消后前端硬拦截禁止再次弹出同一卡片。
  • 粘性路由短路：业务确认回执会话具备粘性（Sticky Routing），直接短路跳过路由 LLM。

5. ⚡ 双重路由优化与意图识别合并

  • 意图识别深度收敛：将原独立意图识别与意图分类收拢合并至单次路由 LLM 调用，大幅削减首字返回延迟与 Token 开销。
  • 结构短路直达：单一候选智能体或特定短路规则直接跳过路由 LLM，响应速度显著提升。
  • 偏好持久化与隔离：支持用户路由偏好持久化存储与会话级实例隔离。

6. 👁️ 纯文本模型图片旁路解析

  • 旁路多模态解析：新增系统配置 multimodal_model_name；当会话使用的当前模型不支持视觉识图时，系统自动调用默认多模态模型旁路解析图片。
  • 无缝文字注入：将图片解析为结构化文字上下文后再交由主模型回答，彻底消除非多模态模型的图片理解断点。

7. 📊 ChatBI 健壮性与明细/依据/引用多维交互

  • 合一展示面板：气泡下方聚合「明细数据 / 执行依据 / 引用来源」多维度合一面板，抽样阈值调整至 500 行。
  • 大结果集兜底：大结果集自动抽样兜底，彻底解决长查询半截回复与前端卡顿问题。
  • 自动缓存合成收口：纠正空结果误述，当 SQL 成功晚于可见正文时强制缓存合成收口，增强连续可视化分析体验。

8. 🛠️ 工作空间、数据门户与任务调度体验优化

  • 工作空间精简：快捷入口收拢为下拉菜单，类型筛选默认折叠；Bash 工具严格绑定到会话工作区目录执行。
  • 黄金报表与数据门户：运行参数新增「今年」预设范围；未启用数据集显式标记不可用并仅返回已启用项。
  • 任务调度与站内通知：提示词约束推送通知禁止夹带中间思考，修复定时器卸载泄漏；站内消息详情支持 Mermaid 与 ECharts 富文本渲染。
  • 菜单更名：原「智能体测评」更名为「智能体调试」（Agent Debug），未选模型时优雅显示「默认模型」。

🐛 缺陷修复与体验优化 (Bug Fixes)

  • 业务确认防重复：修复用户取消后可能再次弹出相同确认卡的问题，增加前端硬拦截机制。
  • 确认卡位置对齐：将确认卡调整到 AI 消息正文下方展示，并在存在确认卡时隐藏 quick 引导避免重复入口。
  • 非多模态报错：修复纯文本模型在用户发送图片时直接报错的问题，实现自动旁路多模态模型解析。
  • 真取消停止：修复点击「停止」按钮仅前端断开连接的问题，实现真正取消后端生成协程。
  • Embed 鉴权加固：修复 EmbedChat 空用户信息报错，加固 Embed Ticket 代客签发权限校验与白名单支持。
  • 移动端横向溢出：修复移动端 AIChat 聊天容器宽度计算错误导致的横向滚动条溢出问题。
  • SQL 收口延迟：修复 SQL 执行成功晚于可见正文时导致的回复截断与状态不一致问题，强制缓存合成收口。
  • ChatBI 空结果误述：纠正 ChatBI 在平台自动重试成功后误报空结果的问题。
  • 任务中心通知正文：提示词强化约束调度任务，仅投递最终分析正文，彻底消除通知中夹带中间规划与思考内容。
  • 定时器卸载泄漏：修复任务中心窗口 resize 监听与 runNow 定时器在组件卸载时未正确清理导致的内存泄漏问题。
  • 工作区 Bash 绑定：修复已配置的 Bash 工具未绑定到会话目录执行的问题，严格锁定当前会话的工作区路径。

⚠️ 破坏性变更与升级注意事项 (Breaking Changes)

🚨 升级特别注意：

1. 必须执行数据库增量脚本：由于引入了运行时状态与多模态配置，升级后请务必执行 MySQL (V119~V121) 或 PostgreSQL (V19~V21)。
2. 嵌入鉴权演进：嵌入聊天已向下兼容旧 Token，但生产环境强烈建议迁移至更安全的 Embed Ticket 代客签发模式。

从 v1.0.10 升级至 v1.0.11 时，请特别注意以下变更：

变更项目 详细说明与迁移指引
AgentScope 运行时注入配置 系统配置新增 agentscope_inject_runtime_state 与 agentscope_inject_time_interval_hours；需执行 MySQL V119 或 PG V19 升级。
系统默认多模态模型配置 系统配置新增 multimodal_model_name，用于纯文本模型会话的图片旁路解析；需执行 MySQL V120 或 PG V20 升级。
思考时间线快照字段 执行历史表 ai_agent_execution_history 新增 process_timeline JSON 字段；需执行 MySQL V121 或 PG V21 升级。
菜单名称变更 原「智能体测评」菜单正式更名为「智能体调试」（Agent Debug）。
Embed 鉴权与 Ticket 机制 引入 Embed Ticket 代客签发权限与域名白名单校验；原有的静态 Token 验证集成方式兼容保留，生产环境推荐迁移至更安全的 Ticket 方式。

📦 快速升级指南 (Upgrade Guide)

⚠️ 升级前置提醒：无论采用源码还是 Docker 升级，请务必先备份数据库，并在服务启动前执行数据库升级脚本！

方式一：源码直接升级（本地 / 虚机部署）

# 1. 拉取最新代码

git fetch origin && git checkout main && git pull origin main

# 2. 更新 Python 依赖（升级至 AgentScope 2.0.6 等）

pip install -r requirements.txt

# 3. 执行数据库升级

./db-prod/apply-sql-native.sh # PG: ./db-prod-pg/apply-sql.sh

# 4. 重新编译前端并启动

cd frontend && npm install && npm run build && cd .. && ./dev.sh

方式二：Docker 容器化升级（生产环境 / 容器集群）

场景 A：从 Release 下载镜像离线加载（推荐）

# 1. 下载并加载镜像归档（按架构选择）

docker load -i nanzi-ai-agent_1.0.11_linux-amd64_*.tar # ARM: arm64_*.tar

# 2. 执行数据库升级

./db-prod/apply-sql-native.sh

# 3. 启动 / 重启容器

cd docker && ./start-nanzi-ai-agent.sh

场景 B：本地 / 服务器自主构建镜像

# 1. 拉取最新代码并执行数据库迁移

git pull origin main && ./db-prod/apply-sql-native.sh

# 2. 构建 v1.0.11 镜像并重启

cd docker && ./build_linux_x86.sh 1.0.11 # ARM: ./build_linux_arm.sh 1.0.11

./start-nanzi-ai-agent.sh
