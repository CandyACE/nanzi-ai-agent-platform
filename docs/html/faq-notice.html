三、高频精华 Q&A 抢先看

💡 Q1：平台容器化部署时，为什么强烈建议安全沙箱配置为 Docker 策略？

解答：当 NanZi 平台自身运行在 Docker 容器内时，若配置为 local 策略，所有 Agent 运行的 Shell 脚本和命令都会在平台主后端容器内直接执行，极易造成平台主环境被污染或资源占满崩溃。
通过挂载 -v /var/run/docker.sock:/var/run/docker.sock 并选择 docker 策略，可以让平台在宿主机上为每个用户拉起独立的沙箱子容器，实现真正的操作系统级多租户安全隔离！

💡 Q2：Skill（技能包）和 Tools（工具）到底有什么本质区别？

解答：打个比方，Tools/MCP 是厨房里的“灶台与锅铲”（提供具体可执行的动作能力，如查数据库、发邮件）；而 Skills 是大厨手里的“菜谱与打法说明书”（规定在什么场景下、先干什么、后干什么、禁止做什么）。同一个智能体挂载相同的工具，更换不同的 Skill 即可执行完全不同的业务 SOP！

💡 Q3：DeepSeek-R1 / QwQ 等深度思考模型调用工具时老报错怎么办？

解答：部分推理模型在输出思考过程（<think>...</think>）时，Tool Call 的原生 JSON 协议可能与常规模型不一致。NanZi 底层内置了智能兼容层，在【模型管理】中为该模型勾选「开启深度思考/推理模型适配」，系统会自动完成 Thinking 字段剥离与工具调用协议归一化。
