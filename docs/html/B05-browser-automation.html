在智能体（AI Agent）落地企业真实业务的过程中，很多高价值数据并没有开放的标准 REST API。它们深藏在内网 OA、ERP、私有数据报表、工单系统或第三方 SaaS 平台中。

当试图让大模型驱动浏览器去处理这些任务时，传统自动化工具（如 Selenium、原生 Playwright）往往会遭遇三大致命瓶颈：

❌ 1. 机械化特征被反爬秒封：0ms 瞬间填入长文本、鼠标瞬移直击正中心，瞬间触发 WAF、极验、Cloudflare 等安全风控；

❌ 2. 现代 SPA 虚拟滚动黑洞：DOM 仅渲染可视区 5 条数据，大模型盲目翻页导致表格拼凑错乱或数据丢失；

❌ 3. 黑盒运行与失控风险：AI 遇到复杂验证码或死循环时，人类无法观察、无法介入，只能任由任务超时崩溃。

01｜架构设计：会话物理沙箱与全双工编排

为了同时满足并发隔离、执行安全性与人机协同毫秒级响应，NanZi 浏览器子系统采用了分层解耦的工业级设计：

🏛️ 四层解耦架构体系

1. 底层驱动层（BrowserWorker）：封装 Playwright Chromium 实例生命周期。提供持久化 user_data_dir、抹除 navigator.webdriver 的 Stealth 脚本注入与 DOM 语义空间解析；

2. 运行时编排层（BrowserRuntime）：会话状态机中枢。维护基于会话 ID 的异步互斥锁（_session_locks）、人机控制权事件分发、快照缓存淘汰与 30 分钟无活动自动析构机制；

3. 实时协议层（FastAPI WebSocket）：提供带时效的 Viewer Token 鉴权、自适应 JPEG 图像流式广播、人工输入事件双向转发及 SSRF 白名单校验；

4. 交互前端（Vue 3 + Tailwind CSS）：自适应等比画面投影、空间命中高亮检测、Chrome 风格多 Tab 与右键菜单、局部框选裁剪与多模态提问联动。

① 会话鉴权与沙箱初始化（Session Provisioning）：
前端触发打开浏览器或对话中大模型首发 browser_open $\to$ 后端校验用户权限并派发带时效的 Viewer Token $\to$ 绑定物理目录 data/browser-profiles/{user_id}/ 启动独立持久化 Chromium Context，注入防检测 Stealth 补丁。

② 全双工握手与帧流广播（Handshake & Stream）：
前端凭 Viewer Token 建立 WebSocket 长连接 $\to$ 订阅 browser_runtime.subscribe_events 队列 $\to$ 后端推送初次 DOM 语义快照、Tab 列表与自适应高质量 JPEG 画面帧 $\to$ 前端完成等比投影与空间坐标映射。

③ AI 工具互斥调用链路（AI Tool Execution & Locking）：
大模型发起 browser_click / browser_fill $\to$ 竞争并获取当前会话异步锁（asyncio.Lock）$\to$ 广播「AI 正在执行」状态并在前端点亮呼吸光圈 $\to$ 拟人引擎执行贝塞尔轨迹移动与自然敲击 $\to$ 动作完成触发 DOM 沉降等待 $\to$ 截取最新 JPEG 帧并广播更新快照 $\to$ 释放锁返回结果给 Agent。

④ 人工即时抢占与平滑回交（Human Takeover & Return）：
用户在画面上触发点击/按键/滚动 $\to$ 前端发送 input 事件 $\to$ 后端毫秒级中断 AI 锁定并标记为「人工操作」$\to$ 原生执行物理操作并返回最新画面 $\to$ 启动 2.5 秒防抖计时器 $\to$ 倒计时结束平滑归还 AI 控制权并派发通知。

⑤ 空闲回收与数据安全擦除（Idle GC & Wipe）：
后台守护协程每隔 5 分钟轮询 $\to$ 若会话无活动超过 30 分钟，自动优雅关闭 Playwright 实例释放显存/内存 $\to$ 登录态 Profile 安全保留在磁盘；用户亦可在个人中心点击「一键清除」，物理抹除底层数据。

02｜拟人仿生：AI 怎么像真人一样操作网页？

很多网站都有风控系统，机器人一操作就会被立刻识别封禁。因为机器人的动作太“假”了：鼠标瞬间瞬移、永远点在按钮最中心的绝对坐标、0毫秒瞬间填完几百个字……

NanZi 在底层给 AI 装上了一套「拟人仿生引擎」，让 AI 的每一个动作都和真人坐在电脑前用鼠标键盘操作一模一样：

🖱️ 1. 鼠标滑过去，而不是“瞬间瞬移”

• 平滑滑行与自然手抖：真人移动鼠标是从起点划一道带弧度的轨迹滑向目标，中途手还会轻微晃动。AI 点击前会分 5~12 步平滑滑过屏幕，每一步都带有微小的人手抖动，彻底告别机器瞬移；

• 随机点在按钮内部，不点死板正中心：真人点按钮绝不可能每次都精准戳在几何绝对正中心。AI 会在按钮内部的偏左、偏右、偏上等安全范围内随机落点；

• 真实物理按压：鼠标移到位置后会自然停顿一下，鼠标按下和抬起之间维持几十毫秒，还原手指真实按压手感。

⌨️ 2. 一个字一个字敲键盘，而不是“直接塞文字”

• 逐字敲击有快有慢：普通脚本是把文字瞬间灌进输入框（耗时 0 毫秒）。AI 则是模拟人手逐字敲击键盘，每个字之间有 30~65 毫秒的正态随机间隔，有快有慢；

• 长文章打一会儿歇一下：遇到很长的段落时，AI 会打完一截停顿 0.1 秒“想想”，再继续打下一截，兼顾打字速度与极高的拟人真实度。

📜 3. 滚轮一截一截滑，滑完还要“用眼睛看一眼”

• 带惯性的滚轮滚动：长页面滚动被拆解为 4~7 次小步长滚轮滑行，带有阻尼感；

• 视觉停顿确认：每次点击或滚动完成后，AI 都会自然停顿 0.1~0.2 秒，就像人眼在看网页是否加载出来一样，绝不进行高频无脑连击。

🧩 4. 专破安全滑块验证码（加速 $\to$ 匀速 $\to$ 减速 $\to$ 抖动回弹）

针对各类拼图滑块，AI 彻底抛弃了被风控秒抓的“匀速直线拖拽”，完美还原真人拉滑块的习惯：起步用力加速 $\to$ 中途快速滑动 $\to$ 靠近缺口时减速慢推 $\to$ 到达终点时不小心拉过头了再往回退 1~2 个像素，滑块通过率大幅飙升！

03｜数据抓取降维打击：DOM 解析 vs 网络层抓包

传统自动化最大的误区是把所有注意力放在 DOM 树解析上。但在面对现代复杂单页应用（SPA）时，DOM 往往是失真的：

📡 为什么网络层抓包能实现“降维打击”？

1. 攻克虚拟滚动（Virtual List）：现代企业报表为优化性能，10,000 行数据在 DOM 中仅保留当前可视的 10 个 <tr> 节点，AI 拼命滚动翻页极易丢失数据。

2. CDP 异步响应监听原理：NanZi 通过在页面初始化时注册异步响应监听通道：
page.on("response", lambda res: handle.network_logs.append(...)) 自动捕获后台发生的 Fetch/XHR 请求及原始 JSON 响应。大模型只需调用 browser_get_network_logs，即可一次性直接读取全量结构化数据，速度提升 20 倍，且绝对完整无遗漏。

3. Cookie 批量注入与免密直登：调用 browser_set_cookies 直接将 Session/Token 注入浏览器上下文，彻底跳过验证码、短信二次认证等繁琐登录链。

04｜28 项全功能工具矩阵与大模型决策优化

拥有工具还不够，大模型如何聪明地选择工具才是关键。NanZi 构建了功能完备的 28 项工具池，并在智能体配置中心完整开放自由勾选：

🛠️ 28 项全功能原子工具矩阵（6 大核心分类完整清单）

1. 基础导航与视口管理（6 项）

• browser_open(url)：打开目标 URL 网页并等待 DOM 加载完毕；

• browser_snapshot()：提取当前页面的 DOM 语义空间快照（自动标记 #ref 编号）并抓取最新 JPEG 画面；

• browser_back()：浏览器历史记录后退一步；

• browser_forward()：浏览器历史记录前进一步；

• browser_reload()：强制重新加载当前网页；

• browser_wait_for(text/selector/timeout)：显式条件等待，直到特定文本出现或元素渲染就绪。

2. 拟人交互与键盘鼠标（8 项）

• browser_click(target_ref)：按缓动贝塞尔曲线平滑移动并拟人点击目标元素；

• browser_fill(target_ref, text)：逐字拟人敲击输入文本（30~65ms/字延时 + 长文分段停顿）；

• browser_scroll(direction/delta_y)：阻尼阶梯式平滑滚轮滚动页面；

• browser_hover(target_ref)：平滑悬停在元素上方（触发悬浮二级菜单或 Tips）；

• browser_press(key)：模拟物理按键（Enter、Tab、Esc、Backspace、方向键等）；

• browser_select_option(target_ref, value)：下拉选框智能选择单项或多项；

• browser_drag(source_ref, target_ref)：元素间拟人化按压拖拽至目标区域；

• browser_slider_drag(slider_ref, distance)：三阶贝塞尔加速度拖拽滑块验证码（专克反爬风控）。

3. DOM 抽取与结构化解析（2 项）

• browser_read_visible()：清洗提取当前视口内真实可见的无噪音正文文本；

• browser_extract_table(target_ref)：智能解析网页表格或 Grid 网格，一键输出 Markdown 表格与 JSON 列表。

4. 多标签页生命周期管理（3 项）

• browser_tabs()：列出当前会话所有打开的标签页列表（含 tab_id、title、url）；

• browser_switch_tab(tab_id)：切换并激活指定的标签页；

• browser_close_tab(tab_id)：关闭指定的标签页。

5. 网络层抓包与凭证管理（3 项）

• browser_get_network_logs(url_pattern)：抓取后台 Fetch/XHR 请求与原始 JSON 响应（直接攻克虚拟滚动列表）；

• browser_get_cookies(domain)：导出当前或指定域名的完整 Cookie 列表；

• browser_set_cookies(cookies)：向浏览器批量注入 Cookie 凭证，免密直登私有系统。

6. 高级执行与文件交互（6 项）

• browser_export_pdf()：将网页渲染导出为矢量 A4 PDF 并发布下载链接；

• browser_upload(target_ref, file_path)：选择并上传本地会话文件到网页上传控件；

• browser_download(url/target_ref)：拦截并下载网页文件到会话目录；

• browser_execute_js(script)：在页面沙箱中执行受控 JavaScript（清理遮罩层/展开折叠区）；

• browser_handle_dialog(action, prompt_text)：预设原生 alert/confirm/prompt 弹窗自动应答策略；

• browser_check_auth()：智能探测当前页面登录凭证与 Token 有效性。

🧠 编排层 System Prompt 决策引导链（Prompt Nudge）

平台在编排层强制规定：遇到报表优先调用 extract_table，遇到接口抓包优先调用 get_network_logs，遇到留存文档优先调用 export_pdf。从规则层面杜绝了模型瞎逛、盲点、乱翻页的算力浪费。

05｜极致协同：空间检视、自适应压缩与毫秒接管

真正的企业级自动化必须将人类控制权置于最高优先级。NanZi 面板提供了多模态感知与交互设计：

🎯 1. 空间命中测试与元素悬停检视（Hover Inspector）

用户鼠标在画面上移动时，前端进行毫秒级 Point-in-Rect 空间碰撞测试，自动在目标元素上方渲染青色半透明虚线框与语义徽标（#ref=12 · button · "立即查询"），底部胶囊实时同步坐标，彻底解决“不知道 AI 到底读没读懂当前页面”的信息黑盒。

⚡ 2. 自适应 JPEG 压缩（体积降低 85%，帧率飙升）

底层截图抛弃了庞大无损的 PNG 方案，升级为自适应高质量 JPEG（quality=75）压缩引擎，单帧体积从 1.2MB 骤降至 40KB ~ 80KB。即便在弱网环境下也能保证毫秒级低延迟画面投屏与零卡顿交互。

🔄 3. 细化动作多态展示与无缝交接

• AI 状态细化：精确区分「AI 正在点击 / 输入 / 读屏 / 导出 PDF / 提取表格 / 脚本执行」；

06｜工程避坑指南：生产环境落地的 5 大硬核经验

⚠️ 1. SSRF 严格防护与私网隔离：AI 具有自主导航能力，必须在底层拦截 127.0.0.1、169.254.169.254（云元数据）等私有 IP 与危险端口，避免内网探测风险；

⚠️ 2. Stale Element 引用自愈：现代前端路由切换后旧 DOM 会被销毁，底层必须实现自动捕获并抛出 BrowserTargetStale，引导 Agent 自动重新获取最新快照，杜绝死锁；

⚠️ 3. 内存与显存防泄漏（30min 自动 GC）：长时间运行无头浏览器会导致内存膨胀，后台必须维护全局活动时间戳，超时无调用自动执行 context.close()；

⚠️ 4. 点击防连击锁（Flight Lock）：在前端发送操作到下一帧快照回传的 250ms 内，界面光标强制置为 cursor-wait，防止用户连击引发并发紊乱；

⚠️ 5. Playwright Crash 守护恢复：当 Chromium 进程偶发被操作系统 OOM-Killer 终结时，运行时通过包装器自动捕获并完成冷启动恢复，对上层 Agent 透明。
