# 元数据同步实时日志设计

## 1. 背景与目标

当前元数据管理页面点击“同步元数据”后，后端通过 FastAPI `BackgroundTasks` 启动同步，接口立即返回；前端只在约 3.5 秒后刷新一次数据集状态。因此用户无法看到读取元数据、生成内容、调用 RAGFlow 等中间过程。

本次目标是为单次手动同步增加实时日志展示：点击同步后打开右侧日志抽屉，持续显示当前任务的阶段、进度、耗时和日志；同步完成或失败后抽屉保持打开，用户手动关闭。日志只服务于当前任务，不提供历史任务记录。

## 2. 方案选择

采用 SSE + Redis 临时事件流。

- 轮询方案请求次数多，实时性和日志顺序都较弱。
- WebSocket 对当前单向进度推送需求过重，需要额外连接管理。
- SSE 与项目现有流式通信模式一致；Redis 事件流可以跨进程传递，并支持短暂断线后的补读。

## 3. 后端设计

### 3.1 接口

保留现有同步接口和权限校验，接口成功启动任务后返回 `task_id`：

`POST /datasets/{dataset_id}/rag/sync`

新增当前任务事件流接口：

`GET /datasets/{dataset_id}/rag/sync/{task_id}/events`

两个接口都必须校验 `element:metadata:sync` 权限、数据集存在且启用，并拒绝重复同步。事件流还必须校验 `task_id` 与 `dataset_id` 的绑定关系，不能订阅其他数据集的任务。

### 3.2 事件协议

每条 SSE data 使用结构化 JSON：

```json
{
  "event": "progress",
  "task_id": "sync_xxx",
  "dataset_id": 17,
  "stage": "ragflow_upload",
  "message": "正在上传元数据到 RAGFlow",
  "progress": 70,
  "elapsed_ms": 1830
}
```

事件类型：

- `started`：任务创建并开始执行
- `progress`：真实同步阶段的进度和日志消息
- `completed`：同步成功，包含最终耗时和结果摘要
- `failed`：同步失败，包含用户可理解的错误信息和可选技术详情

同步服务在真实阶段边界发布事件，不使用与实际工作量无关的虚假固定百分比。任务状态继续回写 `rag_sync_status`；异常路径必须同时发布 `failed` 事件并回写失败状态。

### 3.3 Redis 生命周期

- 每次同步生成不可猜测的 `task_id`。
- 使用 Redis Stream 保存当前任务事件，并维护任务状态/数据集绑定信息。
- 事件和状态设置有限 TTL（建议 30 分钟），不作为历史同步记录。
- SSE 建连时先读取已有事件，再订阅新事件，避免 POST 返回和 SSE 建连之间丢失 `started`。
- 客户端断线不取消后台同步；重新连接时可从最近事件继续读取，超过 TTL 则显示连接已过期并请求一次最终数据集状态。

## 4. 前端设计

在 `MetadataTables.vue` 的数据集详情页使用右侧同步日志抽屉：

- 顶部显示数据集名称、同步状态和耗时。
- 中间按时间顺序追加日志；进行中使用蓝色，成功使用绿色，失败使用红色。
- 底部显示进度条和当前阶段。
- 同步完成后保持打开，显示“同步成功”或“同步失败”；关闭只影响展示，不取消后端任务。
- 页面刷新或抽屉重新打开时，不恢复历史任务，只处理当前仍在运行的 task。
- SSE 断开时保留已收到的日志，并提示“实时日志连接已断开”，不能直接把任务标记为失败。
- 保留现有按钮防重复点击、成功后刷新数据集信息和权限控制。

前端使用支持自定义请求头的 SSE/fetch 流读取方式，以兼容项目现有鉴权方式；不依赖无法携带认证头的原生 `EventSource`，除非现有认证完全由安全 Cookie 提供。

## 5. 数据流

1. 用户点击同步。
2. 前端调用 POST 接口，获得 `task_id`。
3. 后端登记 Redis 临时任务状态，启动后台同步。
4. 前端打开该 task 的 SSE 接口，先读取已有事件，再接收实时事件。
5. 同步服务在各真实阶段发布 `progress`。
6. 成功或异常时发布终态事件并更新数据集状态。
7. 前端展示终态并保持抽屉打开，用户手动关闭。

## 6. 错误处理

- POST 启动失败：不打开日志抽屉，直接显示启动失败原因。
- 同步业务失败：收到 `failed` 后停止等待新事件，但保留完整日志和错误详情。
- SSE 连接断开：展示连接断开提示，保留已有日志；可有限次重连，重连失败不覆盖后端任务状态。
- Redis 不可用：接口返回明确错误，不伪造实时日志；保留现有同步失败回写机制。
- 用户无权限、数据集不存在、任务与数据集不匹配：返回 403/404/400，不泄露其他任务信息。

## 7. 测试与验收

后端：

- POST 返回唯一 task id，并保留原有权限、启用状态和防重复校验。
- SSE 能按顺序收到 `started`、至少一条 `progress`、以及 `completed` 或 `failed`。
- 事件流拒绝其他数据集或无权限用户的 task。
- Redis 临时事件按 TTL 过期，不生成历史记录。
- 同步异常同时产生 `failed` 事件和失败状态。

前端：

- 点击同步后打开右侧抽屉并显示实时追加日志。
- 正常完成、失败、启动失败和 SSE 断线状态分别展示正确。
- 完成后抽屉保持打开，手动关闭有效。
- 不重复发起同步，不破坏原有状态刷新和权限按钮。

验收边界：代码测试覆盖接口、事件协议、权限和前端状态契约；不在 Agent 侧启动开发服务、Docker、RAGFlow 或生产数据库。真实浏览器 SSE、Redis 和 RAGFlow 联调由用户在控制台环境执行。
