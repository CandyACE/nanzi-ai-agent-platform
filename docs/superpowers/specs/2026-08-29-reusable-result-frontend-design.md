# 可复用结果前端入口设计

## 1. 背景

平台已经在服务端为成功且非空的工具调用、子代理调用和 ChatBI 结果保存统一的 `reusable_result`。它与对话历史独立，当前结果保存在 Redis 的 current，最近结果保存在最多 10 条的 stack 中，默认 TTL 为 30 天。

当前前端已有“AI 产物”能力，但它主要展示 Word、Excel、导出文件等可下载产物；尚未展示本次保存的可复用分析结果，也不能让用户查看或选择最近结果。

本设计采用用户确认的 C+B 方案：

- 回复底部提供轻量状态，让用户知道本轮结果已保存或本轮复用了旧结果。
- “AI 产物”抽屉内增加独立的“可复用结果”区域，展示当前结果和最近结果，并允许用户为下一轮分析选择某一条结果。

## 2. 目标

1. 用户能明确知道“本轮结果已保存，可继续分析”。
2. 用户能在当前会话中查看 current 和最近结果栈的安全摘要。
3. 用户能选择某一条最近结果作为下一轮分析上下文。
4. 继续保持当前结果优先、结果缺失时回退原有查询、显式刷新时重新获取的行为。
5. 不把 Redis 临时结果误认为 Word/Excel 等可下载文件。
6. 不向模型增加新的模型可见 tool，不暴露 Redis key、完整工具参数或凭证。

## 3. 非目标

- 不把可复用结果写入对话历史。
- 不让前端直接访问 Redis。
- 不在第一阶段提供跨会话、跨用户的结果检索。
- 不允许用户从前端编辑、删除或延长 Redis 结果 TTL。
- 不改变现有文件产物的下载、鉴权和过期逻辑。

## 4. 现有前端落点

### 4.1 回复操作区

`frontend/src/views/EmbedChat.vue` 已经统一渲染 AI 回复底部操作，包括复制、导出、文件产物、继续分析和链路。这里增加可复用结果状态最合适：它与当前回复一一对应，且不会干扰正文。

状态只在服务端明确返回结果状态时显示：

- `已保存，可复用`
- `已复用上一结果`
- `已回退重新查询`

状态不显示 Redis key、内部 result payload 或完整调用参数。点击“已保存，可复用”打开“我的产出”抽屉并定位到对应结果。

### 4.2 AI 产物抽屉

`frontend/src/components/embed/MyArtifactsDrawer.vue` 继续作为会话级产物入口，但将内容分成两个明确区域：

- `文件产物`：现有 Word、Excel、导出文件列表，行为保持不变。
- `可复用结果`：新增的 Redis 结果摘要列表。

`frontend/src/components/embed/MessageArtifactsDrawer.vue` 仍然只展示某一条 AI 消息生成的文件产物，不承载可复用结果。

这种划分避免用户把“可用于后续分析的临时结果”和“可下载文件”混为一谈。

## 5. 交互设计

### 5.1 回复底部状态

在“继续分析”附近显示低强调的状态文本或胶囊：

```text
继续分析   ✓ 已保存，可复用
```

命中复用时显示：

```text
继续分析   ↻ 已复用上一结果
```

没有结果、结果为空、失败、过期或 Redis 不可用时不显示“已保存”。重新查询仍使用原有操作，不增加额外确认弹窗。

### 5.2 抽屉标签

“我的产出”抽屉提供两个标签：

```text
文件产物 (3)    可复用结果 (4)
```

可复用结果列表默认按保存时间倒序：

- current 标记为 `当前`
- 其余结果显示保存时间和剩余有效期
- 结果类型显示为“数据分析 / 知识库 / 网页 / 文件 / 代码 / 通用结果”等用户可读名称
- 来源显示工具或子代理的展示名称
- 内容只展示截断摘要，不展示完整敏感参数

列表项示例：

```text
本月销售分析结果                         当前
数据分析 · 查数助手 · 2026-08-29 19:37
销售额、订单量和区域排名的查询结果……     还有 29 天
[用于下一轮分析]
```

### 5.3 手动选择结果

点击“用于下一轮分析”不会立即发送请求，也不会覆盖 Redis 的 current。前端保存一个会话级 `selectedReusableResultId`，并在输入区显示：

```text
已选择分析结果：本月销售分析结果                         ×
```

用户发送下一条消息时，前端将该 ID 作为可选请求字段发送。服务端校验该结果属于当前用户和当前会话、未过期且仍可复用；校验失败时清除选择并按正常 current/fallback 逻辑继续。

该选择只消费一次：请求提交后前端清除 `selectedReusableResultId`，防止后续普通消息意外持续绑定旧结果。

以下请求不使用手动选择的旧结果：

- 用户明确要求最新、实时、刷新、重新查询
- 结果类型与本轮请求明显不匹配
- 结果已过期、被清理或读取失败

## 6. 前后端数据契约

### 6.1 SSE 结果状态事件

增加一个不携带正文的状态事件，例如：

```json
{
  "type": "reusable_result_status",
  "status": "saved",
  "result_id": "rr_abc123",
  "result_type": "data",
  "origin_name": "查数助手",
  "created_at": "2026-08-29T11:37:00Z",
  "expires_at": "2026-09-28T11:37:00Z"
}
```

`status` 至少支持：

- `saved`：本轮成功保存
- `reused`：本轮使用了已有结果
- `fallback`：本轮没有可用结果，执行了原有获取流程

前端把事件归并到当前 `Message`，只保留展示所需的字段。历史消息没有该事件时，不补造“已保存”状态。

### 6.2 结果列表接口

新增经过当前用户鉴权的会话级读取接口：

```text
GET /api/v1/chat/reusable-results?conversation_id={id}
```

返回 current 和最近 stack 中仍有效的安全摘要，最多 10 条。建议字段：

```json
{
  "result_id": "rr_abc123",
  "result_type": "data",
  "origin_type": "tool",
  "origin_name": "查数助手",
  "source_type": "internal_structured_data",
  "status": "success",
  "text_excerpt": "销售额、订单量和区域排名的查询结果……",
  "structured_preview": {"row_count": 20, "columns": ["区域", "销售额"]},
  "created_at": "2026-08-29T11:37:00Z",
  "expires_at": "2026-09-28T11:37:00Z",
  "is_current": true
}
```

接口不能返回 `tool_args`、访问令牌、内部 Redis key 或不必要的完整 payload。接口读取失败时，抽屉展示可重试的错误状态，不影响聊天发送。

### 6.3 聊天请求字段

聊天请求增加可选字段：

```json
{
  "reusable_result_id": "rr_abc123"
}
```

服务端将其作为“用户明确选择的本轮上下文”处理，并进行归属、有效期、结果类型和刷新意图校验。未提供时继续现有 current → stack → legacy → fallback 顺序。

## 7. 状态和错误处理

| 场景 | 前端表现 | 服务端行为 |
| --- | --- | --- |
| 本轮成功保存 | 显示“已保存，可复用” | 写入 current/stack 并发送 `saved` |
| 本轮复用 current/stack | 显示“已复用上一结果” | 不重复事实获取并发送 `reused` |
| 结果不存在或过期 | 不显示保存状态；列表显示空/过期提示 | 回退现有查询流程并发送 `fallback` |
| 用户选择结果已失效 | 清除选择并提示“结果已失效，已按正常流程处理” | 忽略该 ID，按安全 fallback 处理 |
| Redis 暂时不可用 | 不显示错误缓存状态；聊天继续 | 读写 fail-safe，沿用原有执行流程 |
| 接口权限失败 | 抽屉显示加载失败和重试 | 不返回跨用户或跨会话信息 |

## 8. 安全和隐私

- 所有列表和选择接口必须使用当前登录用户身份，并校验 conversation ownership。
- 结果摘要需要截断和 JSON 安全序列化，前端按纯文本展示，避免把 Markdown/HTML 当作可执行内容。
- 不向浏览器返回访问令牌、完整敏感参数、Redis key 和内部调度信息。
- 手动选择只作用于下一次请求，不修改 current，不延长 TTL，不跨会话复用。
- 结果删除、会话清理和过期行为继续由后端统一控制。

## 9. 测试和验收

### 前端

- `MyArtifactsDrawer` 能在文件产物和可复用结果之间切换，原文件列表和下载行为不变。
- 空结果、接口失败、过期结果、移动端抽屉均有稳定展示。
- `reusable_result_status` 能正确更新对应 AI 消息的保存/复用状态。
- 点击“用于下一轮分析”只设置一次性选择，不自动发送，不覆盖 current。
- 发送下一条消息后选择 ID 被清除；刷新/最新查询不携带旧结果。
- 现有快捷按钮、继续分析、文件产物、ChatBI 表格和导出契约测试继续通过。

### 后端

- 列表接口只返回当前用户和当前会话结果。
- 结果 ID、过期时间、结果类型和刷新意图校验正确。
- `saved/reused/fallback` 事件字段 JSON-safe，失败和空结果不发送 `saved`。
- Redis 不可用时保持原有查询降级行为。

### 验收边界

静态测试、契约测试和 fake Redis 测试不等价于真实 Redis、真实浏览器和多节点并发验收。实现完成后需要由用户在控制台启动服务，验证真实会话中的：保存、抽屉读取、手动选择、快捷按钮复用、刷新绕过和过期回退。

## 10. 实施顺序

1. 先补充后端安全读取接口、聊天请求可选 result ID 和 SSE 状态事件。
2. 增加前端类型、SSE 归并和一次性选择状态。
3. 改造 `MyArtifactsDrawer` 的标签与可复用结果列表。
4. 在 `EmbedChat` 回复操作区接入状态入口和抽屉定位。
5. 补充前后端契约测试，最后做真实浏览器验收。
