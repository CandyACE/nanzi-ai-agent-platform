# 上下文管理收口设计

## 目标

收口当前 review 中剩余的上下文管理问题：编辑重发后的摘要分支污染、自动路由使用错误模型窗口、模型注册表异常阻断聊天，以及后台语义摘要乱序覆盖。

## 方案

1. 历史截断和清空时清理 debounce 游标、跨轮 digest 与结构化会话摘要；保留单调消息 seq counter，使新分支继续使用递增序号。
2. 上下文采用两阶段准备：
   - 路由前使用配置兜底预算和确定性摘录，不解析具体 agent 模型，也不启动 LLM 摘要。
   - 最终 agent 路由完成并解析目标模型后，按目标模型窗口重新准备最终请求上下文，再允许异步 LLM 摘要。
3. 预算阶段和最终模型信息阶段都捕获模型注册表异常；最终模型信息保留 agent 配置模型身份，并使用默认上下文预算继续执行。
4. 后台摘要保留进程内异步模型，但维护任务引用，并以历史最高 seq + 会话 branch revision 做 Redis 条件写入，旧历史任务不得覆盖已有更新或在截断后复活。

## 边界

摘要属于增强能力，不引入新的持久化任务队列；确定性摘录仍是本轮主链路的正确性保障。后台任务在进程退出时可能丢失，但不会阻塞或破坏当前聊天请求。

## 验证

补充并运行以下回归：

- 截断后旧分支摘要、digest 和 debounce 游标被清理，新分支完整重算。
- 自动路由先完成 agent 选择，再按目标模型窗口重建最终上下文。
- 预算阶段与最终模型信息阶段的 ModelRegistryError 都不阻断聊天。
- 后台摘要不被旧 seq 任务覆盖，且主链路不等待摘要任务。
- 现有上下文、记忆、路由和前端契约测试保持通过。
