# 窄屏消息操作栏横向滚动设计

**日期：** 2026-08-31

## 目标

修复窄屏消息底部操作栏中按钮被压扁、长文本竖向换行的问题。操作项应保持可读和可点击；当总宽度超过消息容器时，用户可以左右滚动查看完整操作项。

## 现状与根因

`frontend/src/views/EmbedChat.vue` 的消息操作栏使用 `flex-nowrap` 和 `overflow-x-auto`，但右侧反馈/扩展操作区域仍通过 `ml-auto` 参与剩余空间分配，部分内部元素没有明确的不可收缩边界。窄屏下，数据/文件等长文本因此被压缩成窄列，出现截图中的竖排效果。

## 设计

在现有消息操作栏内完成最小布局修复：

1. 操作栏保留单行布局和横向溢出能力。
2. 每个操作项及其内部文字、徽标、图标保持 `shrink-0` / `whitespace-nowrap` 语义，禁止按钮内容被压缩或折行。
3. 右侧反馈与扩展操作组也保持最小内容宽度；它仍位于操作项之后，不再通过 `ml-auto` 强行占用窄屏剩余空间。
4. 横向滚动只在实际溢出时出现，桌面宽屏不改变现有视觉与交互。
5. 不改变按钮文案、事件、权限判断、移动端隐藏规则或弹出菜单定位。

## 影响范围

- 修改：`frontend/src/views/EmbedChat.vue` 消息操作栏的布局类名。
- 可能修改：`frontend/src/components/chat/MessageActionMenus.vue`，仅在需要时补充根节点和按钮的不可收缩/不换行约束。
- 测试：新增或补充前端源码契约测试，锁定横向滚动容器、`flex-nowrap`、按钮不可收缩和右侧操作组不可压缩等约束。

## 验收标准

- 窄屏下“数据 / 文件”、Token 统计、继续分析、反馈和更多等操作项保持完整，不出现竖排或文字挤压。
- 操作项超出消息宽度时，消息操作栏可以通过触摸板或手指左右滚动访问全部按钮。
- 宽屏下操作栏仍按现有顺序和样式展示。
- 现有按钮点击事件和菜单行为不受影响。
- 前端契约测试和 `vue-tsc --noEmit` 通过。

## 非目标

- 不重构消息操作栏组件。
- 不增加左右箭头、滚动提示或新的交互按钮。
- 不修改消息内容区、快捷提问按钮或工作空间浏览器。
