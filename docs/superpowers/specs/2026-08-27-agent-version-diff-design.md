# 智能体版本 Diff 对比设计

## 背景

“配置与发布”版本抽屉已经能够查看、克隆、发布和删除智能体版本，但查看归档版本时，用户无法快速确认它与当前线上版本的配置差异。当前版本列表接口已经返回完整版本配置，因此本需求不需要新增后端接口或数据库变更。

## 目标与范围

- 在有当前线上版本时，为非线上版本提供 `Diff` 入口。
- 将被选版本与当前 `status === "PUBLISHED"` 的线上版本进行只读对比。
- 覆盖模型策略、工具、Skills、系统提示词和欢迎语等运行配置。
- 让用户能够快速定位配置变化，同时保留版本号、状态、创建时间和备注等版本元信息。
- 不改变现有查看、编辑、克隆、发布、归档、删除和权限规则。

本需求只处理当前智能体版本列表内的配置比较，不提供跨智能体比较、导出 Diff、历史版本之间任意配对比较或后端审计记录。

## 组件与数据流

### 组件职责

- `AgentVersionsDrawer.vue`
  - 继续负责加载和展示版本列表。
  - 从列表中识别当前线上版本。
  - 在非线上版本的操作区显示 `Diff`，并将选中版本与线上版本传给 Diff 弹窗。
  - 控制 Diff 弹窗的打开和关闭。
- `AgentVersionDiffModal.vue`
  - 接收 `sourceVersion` 和 `publishedVersion` 两个版本对象。
  - 展示版本关系、变化数量和只读配置差异。
  - 不保存、不编辑、不发布、不克隆任何版本。
- `agentVersionDiff.ts`
  - 提供版本配置归一化和差异计算的纯函数。
  - 处理空值、数组、工具对象和欢迎语 JSON，避免表示差异造成误报。

### 数据流

1. 抽屉通过已有 `agentApi.listVersions` 获取版本列表。
2. 以 `status === "PUBLISHED"` 的版本作为当前线上版本；现有后端按版本号倒序返回列表，但 Diff 不依赖列表位置。
3. 用户点击归档版本或草稿版本的 `Diff` 后，抽屉设置待对比版本并打开弹窗。
4. 纯函数对两个版本的运行配置进行归一化，生成变化项。
5. 弹窗按分组渲染变化项；关闭时仅清理本地弹窗状态。

## 交互设计

### 入口

- 归档版本行的操作区在“查看”旁增加 `Diff`。
- 草稿版本也提供相同入口，便于在发布前检查它与线上版本的差异。
- 当前线上版本自身不显示 `Diff`，因为它没有有效的自比较对象。
- Diff 是只读能力，不要求编辑权限；对所有能看到版本列表的用户开放，不复用编辑权限条件。
- 没有当前线上版本时，所有版本均不显示 `Diff`。

### 弹窗结构

弹窗标题为“版本 Diff”，顶部显示“V{源版本号} → 当前线上 V{线上版本号}”以及源版本状态、创建时间和备注。随后显示变化数量。

正文按以下分组展示：

1. 模型策略：主模型、温度、合成模型、合成温度。
2. 工具与 Skills：显示新增项 `+`、移除项 `-` 和同名配置的“已修改”状态；工具配置对象以稳定字段顺序展示。
3. 系统提示词：左右两块只读文本，支持长文本区域滚动，并明确历史版本与当前线上版本方向。
4. 欢迎语配置：启用状态、模式、生成要求和三张卡片的标题、副标题、Prompt。

所有配置分组都显示；配置没有变化的分组显示“无变化”。两个版本完全一致时，弹窗顶部额外显示“与当前线上版本配置一致”。本次不增加“仅显示变化”切换，避免在小尺寸弹窗中隐藏对比上下文。

版本号、ID、状态、创建时间和备注不计入运行配置差异；备注只在顶部作为元信息展示。

## 比较规则

- `null`、未定义和适用字段的空值统一为可展示的空值，不能因为历史版本缺少新字段而导致整个 Diff 失败。
- 标量字段按值比较。
- 系统提示词按文本比较；实现至少要展示两侧完整文本和变化状态，不能截断导致用户无法核对。
- 工具和 Skills 按集合内容比较，工具对象按工具名匹配并稳定排序字段；同名工具的配置字段变化标记为“已修改”，数组顺序变化不应被误报为新增和删除。
- 欢迎语按配置字段和卡片位置比较，卡片内部字段变化要能定位到具体字段。
- Diff 计算结果应包含稳定的字段标识、显示标签、源版本值、线上版本值和变化类型，供组件渲染和单元测试复用。

## 权限、状态与错误处理

- 查看和 Diff 均为只读，不增加归档版本编辑能力；Diff 的可见性与 `agent.is_editable` 无关。
- 克隆入口继续使用现有 `agent.is_editable !== false` 条件，不与 Diff 权限混用。
- 发布、删除、版本编辑和版本刷新流程保持原实现。
- 当前线上版本缺失时不渲染 Diff 入口。
- 如果某个字段格式异常，比较函数将其转为安全的可读值并继续展示其他分组；不因单个字段异常关闭弹窗。
- Diff 弹窗不发起额外网络请求，因此不新增加载失败分支。

## 测试与验收

### 自动化测试

- 前端纯函数测试覆盖：相同配置、标量变化、系统提示词变化、工具新增/移除、Skills 顺序变化、欢迎语字段变化、空值和缺字段。
- 前端契约测试覆盖：归档/草稿版本显示 Diff、当前线上版本不显示、点击时传入源版本和当前线上版本、弹窗只读文案与分组存在。
- 运行对应前端测试。
- 运行 `cd frontend && ./node_modules/.bin/vue-tsc --noEmit`。
- 运行涉及文件的 `git diff --check`。

### 人工验收

1. 在截图对应的版本抽屉中，归档 V22 行显示“查看 / Diff / 克隆 / 删除”，点击 Diff 后居中的只读弹窗显示 V22 与当前线上 V23 的差异。
2. 草稿版本同样可以 Diff；当前线上 V23 不出现 Diff。
3. 修改权限不足的用户仍可查看 Diff，但不能因为 Diff 入口出现而获得编辑、克隆或发布能力。
4. 对比完成后关闭弹窗，原版本列表和原有操作状态不变；查看归档版本仍不可保存修改。
5. 若智能体没有线上版本，版本列表不显示 Diff，其他版本操作仍正常。

## 非目标

- 不新增后端 Diff API、数据库字段或迁移。
- 不改变版本号分配、发布就绪校验、归档和删除规则。
- 不实现任意两个历史版本的自定义选择对比。
- 不提供 Diff 导出、审计日志或批量比较。
