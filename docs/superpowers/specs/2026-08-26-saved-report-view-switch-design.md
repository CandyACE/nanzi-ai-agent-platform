# 固化报表卡片/列表视图切换设计

## 背景

固化报表当前主要以卡片展示。完整数据门户空间较宽，适合在工具栏直接提供卡片与列表两个视图；右侧数据门户 panel 横向空间有限，完整的并排切换控件会挤压标题和操作，因此需要使用更紧凑的视图胶囊。

## 目标

- 在完整数据门户固化报表 Tab 中提供清晰的卡片/列表并排切换。
- 在右侧 panel 中提供紧凑的卡片/列表切换，不遮挡报表标题和操作。
- 两个入口的视图偏好彼此隔离，并在刷新后保留。
- 两种视图复用同一套报表数据、权限状态、运行、详情和更多操作，不改变业务行为。
- 默认继续使用卡片视图，避免升级后已有用户的首屏布局突变。

## 入口与状态

### 完整数据门户

`DataPortalReportSection` 在 `compact=false` 且 `manage=true` 时展示并排的「卡片 / 列表」切换按钮。视图偏好保存为独立的 localStorage key，仅影响完整报表中心。

### 右侧数据门户 panel

`DatasetCapabilityMenu` 在固化报表工具栏展示紧凑胶囊按钮。点击后在卡片和列表之间切换，使用独立的 localStorage key，仅影响右侧 panel。默认值为卡片视图。

## 列表布局

列表项复用 `SavedReportItemCard` 的数据和事件，增加 `variant="list"`：

- 左侧：报表名称、归属/权限状态、业务标签。
- 中部：最近运行时间、运行次数和订阅状态。
- 右侧：运行、详情、更多操作。
- 无权限时继续保留禁用状态和权限提示。
- 右侧 panel 的窄宽度下，非核心文本截断，操作按钮保持可点击且不换行遮挡。

## 交互与边界

- 切换视图只改变布局，不改变当前筛选、搜索、分页和已加载报表。
- 运行、详情、编辑、收藏、置顶、分享、复制、删除和订阅事件保持现有 emit/handler 链路。
- localStorage 不可用或值非法时回退到 `card`。
- 小屏和右侧 panel 不展示完整数据门户的宽版切换组，只使用对应入口的紧凑控件。

## 测试

- 前端契约测试验证两个入口的切换状态、独立 localStorage key、默认卡片、列表 variant 及操作事件仍存在。
- 执行数据门户与固化报表相关前端回归测试。
- 执行前端 TypeScript 检查和 Vite 构建，确认两种模板布局均可编译。
