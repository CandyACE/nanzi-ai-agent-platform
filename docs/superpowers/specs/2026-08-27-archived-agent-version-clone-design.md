# 归档智能体版本复制新建设计

## 背景

智能体“配置与发布”抽屉中的归档版本目前只能查看或删除。归档配置本身必须保持不可编辑，但用户需要基于历史配置快速创建一个新的草稿版本。

## 目标与范围

- 在归档版本的操作区增加“克隆”入口。
- 克隆后打开现有版本编辑器，复制源版本配置并作为新草稿处理。
- 保持归档版本只读，不更新或覆盖源版本。
- 复用现有前端事件、编辑器初始化逻辑和后端创建版本接口。

本次不新增后端 API，不改变版本状态规则、权限规则或删除规则。

## 交互与数据流

1. 用户在“归档历史”中查看归档版本。
2. 当当前用户拥有智能体编辑权限时，归档版本显示“克隆”；无编辑权限时不显示该按钮。
3. 点击“克隆”触发已有的 `create-version` 事件并传入源版本。
4. 父层沿用 `openVersionModal(sourceVersion, true)`：复制配置字段，清空 `id` 与 `version_number`，将状态设为 `DRAFT`，并保留现有克隆说明。
5. 用户在编辑器中修改并保存时，沿用创建版本接口；后端根据该智能体的最大版本号分配新版本号。
6. 源归档版本不参与更新，仍以 `ARCHIVED` 状态展示。

## 权限与只读边界

- 归档版本查看仍通过现有编辑器只读机制控制，不能直接保存修改。
- “克隆”入口与活跃版本现有入口使用相同的 `agent.is_editable !== false` 条件。
- 克隆产生的是新草稿，是否发布仍由现有发布流程和就绪校验决定。

## 错误处理

本次不引入新的错误分支。克隆打开失败、草稿保存失败和发布失败继续由现有编辑器及父层的提示逻辑处理；后端创建接口的权限校验和版本号分配保持不变。

## 测试与验收

- 增加前端源码契约测试，确认归档区域渲染“克隆”入口、使用编辑权限条件，并向 `create-version` 传入归档版本。
- 运行该前端契约测试。
- 运行前端契约测试集合、`vue-tsc --noEmit` 或仓库现有等价类型检查；若环境阻塞，单独记录阻塞原因。
- 人工验收：无编辑权限不显示克隆；有编辑权限点击归档版本克隆后打开新建草稿，原归档版本仍可查看且不可保存。

## 非目标

- 不允许直接编辑归档版本。
- 不新增后端克隆接口或数据库迁移。
- 不改变活跃版本、发布、归档和删除行为。
