# 工作空间浏览器视图切换设计

## 目标

优化工作空间浏览器的文件操作体验：替换底部多选按钮中不直观的 SVG 图标，增加搜索后的手动刷新入口，并支持列表视图与文件夹网格视图切换。

## 范围

- 修改 `frontend/src/components/embed/WorkspaceBrowserDrawer.vue`。
- 不新增后端接口；刷新继续调用已有目录读取接口。
- 默认保持列表视图，避免影响已有用户习惯。
- 不改变文件权限、搜索、类型筛选、排序、分页、预览、挂载、右键菜单和上传逻辑。

## 交互设计

### 多选按钮

底部悬浮多选按钮改用 Heroicons 的语义化图标：普通状态显示复选框/选择图标，开启多选后显示 `XMarkIcon`。保留现有圆形悬浮按钮、状态色、标题和无障碍标签。

### 刷新按钮

搜索框右侧增加按钮，使用 `ArrowPathIcon`。点击后调用 `refreshDirectory()`，刷新当前目录并保留搜索词、子目录选项和类型筛选。请求期间按钮禁用并旋转，避免重复触发。

### 视图切换

文件列表容器的顶部工具行增加“列表 / 文件夹”分段切换。状态为组件本地 `ref<'list' | 'grid'>`，默认 `list`，本轮不持久化到后端或本地存储。

两种视图共用 `paginatedDisplayItems`，因此搜索、类型筛选、排序和分页结果一致：

- 列表视图：保留当前表格布局和列信息。
- 文件夹视图：使用响应式网格卡片，文件夹和文件都显示；文件夹优先行为沿用现有排序。卡片显示现有文件图标、名称、类型、大小和修改时间。
- 单击、双击、右键菜单、移动端长按、多选和批量挂载复用现有处理函数。
- 搜索或类型筛选返回递归结果时，卡片仍显示来源目录提示，避免用户误以为项目位于当前目录。

## 组件实现边界

在现有组件内增加最小状态和模板分支，不拆分新组件。新增的网格分支只负责布局；数据转换、权限判断、选择状态和事件处理继续由现有函数负责。刷新按钮不直接操作 `items`，统一经过 `refreshDirectory()`，保证状态清理和错误提示逻辑一致。

## 测试与验收

- 增加前端源码契约测试，验证刷新按钮调用 `refreshDirectory`、使用 `ArrowPathIcon`，视图状态包含 list/grid 且默认列表，网格分支使用共享展示数据和现有双击/多选处理函数。
- 运行相关前端契约测试。
- 运行 `./node_modules/.bin/vue-tsc --noEmit`（工作目录为 `frontend`）。
- 不启动服务；未进行真实浏览器、后端接口或上传后刷新验收，由用户在控制台启动服务后手动确认。

## 取舍

选择在单组件内实现，是因为当前列表的数据、选择、权限和交互处理已经集中在该组件中。抽取独立网格组件会增加事件和状态传递；仅修改 CSS 又无法清晰表达两种视图的不同信息布局。
