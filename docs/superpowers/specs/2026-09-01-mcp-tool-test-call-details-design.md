# MCP 工具测试台调用详情设计

## 目标

在 MCP 工具测试台中增加“调用详情”Tab，让用户点击“运行测试”后可以查看本次调用实际发送的参数，以及 MCP 返回的成功结果或错误详情。

## 交互设计

- 保留现有“参数输入”Tab，默认打开时仍展示参数表单。
- 测试成功或失败后自动切换到“调用详情”Tab，避免用户需要再次点击查结果。
- “调用详情”Tab 按上下顺序展示：
  1. 本次调用认证信息：沿用现有脱敏展示，不展示可重放的完整断言值。
  2. 请求参数：展示实际发送给后端的 `{ arguments: args }` JSON。
  3. 响应结果：成功时展示现有格式化 JSON/Markdown/文本结果；失败时展示错误消息。
- 请求参数和响应结果均使用等宽代码块，支持横向滚动；响应结果沿用现有复制能力，请求参数也提供复制按钮。
- 尚未运行测试时，“调用详情”Tab 可见但显示提示“运行测试后查看本次调用详情”，不伪造请求或响应内容。
- 重新选择工具或重新打开测试台时，Tab 恢复到“参数输入”，清空旧的调用详情。

## 数据流

- 点击“运行测试”前，将当前 `args` 快照为本次请求详情，避免请求完成前用户修改表单造成展示内容与实际发送内容不一致。
- 请求成功时保存 `res.data.result` 并按现有 `formattedResult` 逻辑渲染。
- 业务失败或网络异常时保存错误消息，调用详情显示失败状态和错误文本。
- `mcpAuth` 继续只使用后端返回的脱敏字段。

## 实现边界

- 只修改 `frontend/src/components/system/McpToolTester.vue` 及其前端契约测试。
- 不修改后端接口；请求详情由前端根据已发送的请求体生成。
- 不引入新的 UI 组件库或状态管理。

## 验证

- 契约测试检查 Tab 文案、请求快照、自动切换、空状态和复制入口。
- 运行 MCP 工具测试台前端契约测试。
- 运行 `vue-tsc --noEmit` 做类型检查；不启动 `./dev.sh`，真实 MCP 服务调用由用户在控制台验证。
