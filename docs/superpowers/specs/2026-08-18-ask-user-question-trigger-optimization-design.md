# `ask_user_question` 主动互动触发优化设计

## 目标

优化通用助手与知识库助手中的 `ask_user_question` 触发边界，使“随便问我几个问题”“考考我”“我不知道怎么提问，你引导我”等明确的互动请求稳定进入提问卡，同时保留任务澄清场景的严格门槛，避免普通闲聊和可安全推断的问题被频繁打断。

本次不修改 ChatBI 的轮次分类、澄清卡或数据查询执行门禁。

## 当前问题

`ask_user_question` 已作为系统隐式工具注入执行器，但当前提示词主要只允许两种情况：缺少会实质改变结果的关键输入，或存在必须由用户选择的业务分支。用户明确要求“先问我”“考考我”并未被定义为高优先级触发信号，因此模型通常会返回文字问题列表，而不是调用工具。

## 触发分层

### 主动互动模式：直接触发

检测到用户明确要求助手通过提问完成互动、引导、测验或需求访谈时，直接生成 `ask_user_question` 工具促发，并在首个模型调用中优先选择该工具。

覆盖表达包括：

- 随便问我几个问题、问我一些问题、你问我答；
- 考考我、测试一下我、给我做个小测验；
- 我不知道怎么提问、你引导我、你一步一步问我；
- 先问我几个问题再帮我制定方案/写作/规划；
- 一个一个问、逐个问、不要一次问完；
- 通过提问了解我的需求/偏好/目标。

否定表达（如“不要问我”“不用提问，直接回答”）必须排除。

### 决策收集模式：满足重要分支时触发

当多个选择都会显著改变后续结果，且无法依据上下文安全确定时，调用工具询问用户。包括输出受众、目标、范围、优先级、风格、数据集/知识库和业务口径等。

### 任务澄清模式：维持严格门槛

仅当缺少信息会实质阻塞当前任务，或存在无法安全消解的歧义、冲突和资源选择时，调用工具。可以安全使用默认值时直接继续，并在回答中说明假设。

### 不触发

- 只要求“列出几个问题”，但没有要求逐个询问用户；
- 简单事实问答、已有上下文可以确定的问题；
- 可由当前工具、用户画像或会话历史安全确定的信息；
- 写入/修改/删除业务数据的最终确认（继续使用 `request_user_confirmation`）；
- 后台自动化、定时任务和无人值守流程；
- 当前会话已有待回答问题卡；
- 用户明确要求停止提问或直接给答案。

## 执行策略

1. 新增无额外 LLM 调用的显式互动意图识别器，供通用助手的 Tool Preflight 和知识库助手的 AgentScope 首轮调用共用。
2. 命中主动互动模式且 `ask_user_question` 可用时，生成强制首步工具促发；工具不可用时不得伪造卡片，只能降级为文字说明。
3. 当前“一轮一个问题”协议保持不变。用户回答后以新一轮会话继续；如果处于主动互动语境，下一轮可以继续生成新的问题，直到用户停止或问题已无信息增益。
4. 知识库助手在需要基于文档提问时，先完成已有知识库预检索，再调用 `ask_user_question`；问题内容必须受已检索内容约束。

## 可观测性

主动互动促发应沿用现有 `tool_preflight` 日志，并明确标记 `ask_user_question`、命中原因和强制首步状态，便于区分“模型自主调用”和“平台显式互动促发”。

## 验收标准

- “随便问我几个问题”“考考我”“我不知道怎么提问，你引导我”“先问我再帮我规划”在通用助手中命中 `ask_user_question` 强制首步促发。
- 同样的主动互动表达在知识库助手中首轮 AgentScope 调用被强制指向 `ask_user_question`，且不破坏知识库预检索和引用链路。
- “给我列几个问题”“不要问我，直接回答”“不用提问”不触发主动互动促发。
- 用户回答、取消、已有 pending、业务确认和后台自动化路径保持原有行为。
- 不改变 ChatBI 执行器的澄清分类和 SQL/Schema 门禁。
