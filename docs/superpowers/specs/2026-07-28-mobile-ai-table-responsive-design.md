# 移动端 AI 消息表格 A+B 自适应设计

## 背景

当前 `MessageRenderer.vue` 将 Markdown 表格包裹在 `.markdown-table-scroll` 中，`EmbedChat.vue` 统一设置表格 `min-width: 680px`，电脑端阅读清晰，但移动端需要用户横向拖动，且滚动意图不明显。

## 目标

- 保持电脑端现有表格视觉和交互不变。
- 移动端常见的少列表格尽量一屏完整显示。
- 移动端多列表格不依赖横向滚动，字段名和值在纵向布局中完整可见。
- 多列表格默认卡片视图，同时允许用户临时切换回可横向滚动的完整表格视图。
- 保留 HTML table 语义，避免影响复制、Markdown 渲染和桌面端样式。
- 不改变图表切换出的独立“表格视图”；本次只处理 AI 消息正文中的 Markdown 表格。

## 方案

采用 A+B 混合策略：

### A：少列表格自适应压缩

当表格列数不超过 3 列时，移动端移除 `min-width: 680px`，使用 `table-layout: fixed`，缩小字号和单元格内边距，并允许表头和内容换行。表格继续以真实行列结构呈现，适合指标、数值、备注等简单结果。

### B：多列表格转纵向信息卡片

当表格列数超过 3 列时，渲染阶段给表格增加移动端卡片标记，并为每个 `td` 注入对应表头的 `data-label`。移动端通过 CSS 将每个数据行显示为一张纵向卡片：每个单元格显示“字段名 + 值”，不隐藏字段，不要求横向滚动。桌面端继续保持普通表格。

卡片模式在移动端额外显示“表格”切换按钮。切换后当前表格恢复原始宽表布局和横向滚动，并把按钮改为“卡片”；切换状态只保存在当前表格 DOM 节点，不持久化、不影响其他 AI 消息表格。

## 判定与容错

- 表格无表头时不执行 B，移动端沿用 A 的压缩表格布局。
- 表头与单元格数量不一致时，缺失标签使用“第 N 列”兜底，不丢弃数据。
- `colspan`/`rowspan` 等复杂 Markdown 生成结果不做激进改写，保留 A 的表格布局，避免破坏语义。
- 表格为空或解析异常时不增加额外占位 UI。

## 交互与可访问性

- A、B 都保留 `<table>`, `<thead>`, `<tbody>`, `<th>`, `<td>`，不把数据转换成纯文本。
- B 的 `data-label` 只作为移动端视觉标签，单元格原文本不变。
- 不新增必须点击或必须发现的横向滚动入口。
- 切换按钮使用明确的 `aria-label` 和 `aria-pressed` 状态，默认卡片视图不依赖横向滚动。
- 桌面端不显示移动端卡片标记，也不改变当前主题色、边框和斑马纹规则。

## 验证

- 增加前端契约测试，覆盖：列数阈值、表头标签注入、无表头/错位表头容错、移动端 A/B CSS 关键规则、桌面端 `min-width: 680px` 保留。
- 运行现有 `tests/frontend/test_message_renderer_contract.py` 与新增定向测试。

## 非目标

- 不重写 Markdown 解析器。
- 不修改 AI 返回内容格式。
- 不改造图表、DatasetCapabilityMenu 或 ChatLogs 等其他表格渲染面。
- 不启动 `./dev.sh` 或其他项目服务脚本。
