# 个人工作台信息密度优化设计

## 背景

当前工作台在真实数据较少时会出现三类问题：顶部“今日运行正常”与“可继续 4 项”语义不一致；最近会话可能出现重复问题；最近产出为空时右侧留下大面积空白。目标是提升决策信息密度，不通过假数据填充页面。

## 目标

1. 摘要先表达用户下一步要做什么，再表达系统是否正常。
2. 同一会话只展示一条最近可继续记录，避免重复卡片。
3. 最近产出为空时提供明确的数据门户入口，并避免空白区域过高。
4. 保留真实助手、场景和定时任务入口；没有真实数据时显示引导，不编造运行进度。

## 非目标

- 不把 AgentScope 当前会话级待确认事项放入工作台。
- 不增加虚假的运行百分比、预计时间或统计数字。
- 不改变“我的工作台”路由和既有权限模型。

## 方案

后端在 `WorkbenchHomeService` 的聚合边界内对 `resume_items` 按 `conversation_id` 去重；保留发生时间更新的记录，并在标题/副标题中使用真实会话信息。摘要字段仍由前端根据 `attention`、`running_items`、`resume_items` 和 `latest_results` 数量计算，空状态使用已有动作路由。

前端将 quiet 状态的顶部提示改成“可继续/有新产出/今日运行正常”的优先级文案；将最近会话与最近产出采用自适应两栏布局，产出为空时使用紧凑 CTA 空态；助手区域在有数据时保留快捷入口，在无数据时提供打开助手或浏览场景包动作。组件继续复用现有 WorkbenchSectionHeader、WorkbenchItemMeta 和路由动作。

## 验证

- 后端测试覆盖会话去重、摘要模式和稳定排序。
- 前端契约测试覆盖摘要文案、空态 CTA、响应式布局和现有动作入口。
- 运行工作台相关 pytest、前端契约测试、Python 编译检查和 `git diff --check`。
