# 通用任务能力缺口与临时方案提示词设计

## 背景

当前平台默认提示词已经覆盖 Bash、工作区路径、命令存在性检查和敏感工具确认，但这些规则主要描述“已有工具如何使用”。当用户提出一个没有完全匹配的专用工具、Skill 或 MCP 的任务时，提示词没有统一指导智能体判断能力缺口、组合已有能力、生成临时脚本或向用户请求依赖安装确认。

## 目标

增加一段平台级、任务类型无关的默认行为规则，使普通用户只需描述目标，智能体就能在权限范围内判断是否可以用已有工具或临时程序完成任务，同时保持以下边界：

- 不因缺少同名专用工具而直接拒绝可完成的任务；
- 不把提示词变成新的权限授予机制；
- 不默认静默安装依赖或执行有副作用操作；
- 没有执行能力时不声称已经完成；
- 不把临时脚本自动注册成平台工具或 MCP。

## 方案

在 `AgentServicePrompts` 中增加一个固定的平台级“任务能力缺口与临时方案”段落，并在平台全局提示词组装时注入。规则按以下顺序指导模型：

1. 明确用户要交付的结果、输入、范围和副作用；
2. 优先使用当前已绑定的专用工具、Skill、MCP 和隐式工具；
3. 如果没有完全匹配的能力，评估当前已绑定的 Bash、文件、Python/代码执行或其他工具能否组合完成；
4. 可以组合完成时，先检查命令、解释器和依赖，优先使用已有依赖或标准库；
5. 如需安装软件包、浏览器、命令行工具或其他运行依赖，先说明名称、用途、来源、影响范围和风险，并等待用户确认；
6. 获得确认后，临时脚本或辅助文件优先放入当前会话工作区，执行后验证结果并按用户要求交付；
7. 需要外部写入、批量修改、发送消息、删除文件、付费、生产变更或其他明显副作用时，单独请求确认；
8. 没有对应执行能力时，只能输出方案、代码或待执行文件，并明确说明未实际执行；
9. 不得通过提示词自行扩大工具权限、访问其他用户/会话资源、注册正式工具或 MCP；长期复用需求应建议走正式工具、Skill 或 MCP 配置流程。

## 注入与权限边界

- 该段落不依赖具体任务类型，所有普通交互都可以理解；实际执行仍只允许使用本轮挂载的工具。
- Bash、Write、Edit、代码执行等工具仍遵守现有工具确认、用户禁用工具、命令黑名单、路径沙箱、超时和部署级权限。
- 不新增能力缺口检测器、不改变 Tool Nudge 的相关度算法、不新增自动安装工具 API。
- 已有更具体的工具说明优先于这段通用规则；通用规则只补充“没有完全匹配能力时如何收敛”。

## 失败与降级行为

- 工具未绑定：说明当前缺少执行能力，并给出可复制的脚本或下一步配置建议。
- 依赖未安装但无需联网安装：优先改用标准库或已存在的命令/库。
- 依赖安装需要确认：说明待执行命令和风险，等待确认，不得声称已安装。
- 工具调用被拒绝、超时或结果不足：如实报告实际状态，不把模型生成的代码或计划当成事实结果。
- 任务要求长期复用：建议管理员配置正式工具/MCP 或创建受控 Skill，不在当前会话中伪造注册成功。

## 验证范围

新增提示词契约测试，至少覆盖：

- 平台全局提示词包含通用能力缺口策略；
- 有执行工具时提示检查环境、优先复用依赖、依赖安装先确认；
- 无执行工具时提示不得声称已执行；
- 提示词明确不授予新权限、不自动注册 MCP/正式工具；
- 现有工具确认段落和无敏感工具时的注入边界不回归。

本次不进行真实依赖安装、外网抓取、服务启动或浏览器验收。
