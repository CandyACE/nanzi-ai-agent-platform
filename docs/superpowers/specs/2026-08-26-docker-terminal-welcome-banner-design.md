# Docker 容器终端欢迎语与环境说明设计

日期：2026-08-26  
范围：`frontend/src/components/chat/DockerTerminalModal.vue` 及其前端契约测试  
状态：已确认并实现

## 1. 背景与目标

当前容器终端首次打开时，将一段普通文本作为伪命令输出：

```text
Connected to Docker Sandbox container [...]
Working Directory: /workspace
Type any bash command to execute inside the sandbox.
```

这段提示不能充分说明工作目录、文件同步、只读挂载、临时数据和容器生命周期，也无法对不同类型的信息做颜色区分。

本次设计目标是：用户每次打开“进入终端”时，先看到一条结构化、可扫读、带颜色语义的中文欢迎信息卡；信息必须符合当前 Docker workspace 的实际挂载和生命周期契约，并且不改变命令执行行为。

## 2. 已确认的用户体验

### 2.1 展示频率

每次终端从隐藏状态切换为显示状态时，追加一条欢迎信息卡。

- 用户清屏后，本次打开期间不自动恢复。
- 关闭终端再重新打开时，再次显示一条欢迎信息卡。
- 欢迎信息使用当前容器短 ID和当前工作目录；工作目录后续由命令执行结果更新时，顶栏和新的欢迎卡使用最新状态。

### 2.2 视觉方向

采用 A「结构化信息卡」：

- 绿色：已连接、可保留/已同步
- 蓝色：当前路径和目录信息
- 紫色：平台运行资源
- 灰色：解释性文字
- 黄色：生命周期与注意事项
- 红色：临时内容和风险警示

欢迎卡使用结构化 DOM 和 Tailwind/CSS 类渲染，不使用 ANSI 转义序列，也不把颜色控制字符写入普通命令输出。

## 3. 欢迎信息内容

欢迎卡按以下层级展示：

```text
Docker 沙箱终端
● 已连接        容器：<short-container-id>
工作目录        <current-workdir，默认 /workspace>

文件与同步
✓ 可写 / 会保留     /workspace
  这里的代码和文件会同步到宿主机用户工作区

◆ 运行资源          /workspace/skills
  平台技能运行快照，不建议手动修改

🔒 只读              /workspace/public/docs
  平台公共文档，只能读取

× 临时内容           /tmp、运行中的进程、非挂载路径文件
  容器停止、回收或重建后不保证保留

生命周期
停止 / 空闲回收：释放容器资源，/workspace 文件保留
重启 / 销毁：删除旧容器，/workspace 文件保留；
              临时进程和容器内临时数据消失

⚠ 安全提示
命令会直接作用于当前沙箱。删除文件、安装依赖、联网或启动后台进程前，
请先确认路径和影响范围。
```

### 3.1 路径与挂载边界

- `/workspace` 是用户主要工作区，当前 Docker workspace 以读写方式绑定到宿主机用户工作区；其中的代码和文件在停止、空闲回收和重启后保留。
- `/workspace/skills` 是独立的 Docker 技能运行快照，不是普通代码目录。当前实现将其作为独立运行挂载提供给容器，因此欢迎语只提示“运行资源”和“不建议手动修改”，不宣称它是只读目录，也不鼓励用户在此修改技能。
- `/workspace/public/docs` 是平台公共文档的只读挂载，欢迎语明确显示为只读。
- 不展示宿主机真实物理路径，不把平台容器的 `/app/data` 误标为用户容器内可直接操作的目录。

### 3.2 生命周期边界

- 停止容器：当前实现清理运行时缓存并停止 Docker 容器；用户主工作区文件仍在宿主机绑定目录中。
- 空闲回收：当前实现回收空闲 Docker workspace 运行资源；用户主工作区文件不随运行时缓存一起删除。
- 重启容器：当前实现强制删除旧容器，再创建并启动新的容器；绑定的 `/workspace` 文件保留，旧容器内进程和未落在持久挂载中的临时内容不保留。
- 对容器内非持久路径、运行中进程、临时安装状态不作持久化承诺；提示统一使用“不保证保留”，避免把停止和销毁混为同一语义。

## 4. 实现方案

### 4.1 前端组件

在 `DockerTerminalModal.vue` 中：

1. 为命令记录增加欢迎卡可识别的记录类型，或使用等价的结构化欢迎记录；普通命令记录的字段和渲染路径保持不变。
2. 抽取创建欢迎记录的逻辑，避免在 `watch(show)` 中重复拼接长文本。
3. 将欢迎记录用独立模板渲染为信息分组、路径标签、生命周期说明和安全提示。
4. `show` 由 `false` 变为 `true` 时始终插入新的欢迎记录；`clearTerminal()` 只清空当前记录，不修改后续重新打开时的展示规则。
5. 继续沿用现有 `containerId`、`currentWorkdir`、快捷命令、历史命令、Docker exec API、错误处理和复制逻辑。

不新增后端字段、不新增 API、不传递宿主机真实路径，也不改变 Docker mount 或容器生命周期逻辑。

### 4.2 可访问性与降级

- 颜色不是唯一信息载体；每个状态同时有中文文字标签。
- 容器 ID 缺失时继续显示现有的 `container` 回退值。
- 当前工作目录缺失时使用 `/workspace`。
- 普通命令输出仍按现有文本方式显示；欢迎卡渲染异常不应阻断命令输入和执行。

## 5. 数据流与交互

```text
打开终端
  -> show 从 false 变为 true
  -> 前端根据 containerId/currentWorkdir 创建欢迎记录
  -> 结构化信息卡显示在终端输出区
  -> 用户清屏或执行命令
  -> 继续使用现有 POST /api/v1/sandbox/docker/workspace/exec
  -> 命令返回的 workdir 更新当前提示路径
```

欢迎卡只描述环境，不参与命令执行、权限判断、Docker workspace 初始化或容器状态查询。

## 6. 测试与验收

### 6.1 自动化测试

在现有前端终端契约测试基础上增加聚焦断言，至少覆盖：

- 欢迎记录使用结构化类型或等价的独立欢迎渲染分支。
- `show` 每次打开都会创建欢迎记录，而不是只在 `records.length === 0` 时创建。
- 欢迎内容包含 `/workspace`、`/workspace/skills`、`/workspace/public/docs`、宿主机同步说明、生命周期说明和安全警示。
- 欢迎卡包含绿色/蓝色/紫色/黄色/红色语义类或等价稳定样式标记。
- 普通命令仍调用现有 Docker exec API，快捷命令和清屏逻辑不被移除。

运行聚焦前端契约测试，并执行 `vue-tsc --noEmit`。如环境允许，再执行相关前端测试集合；环境依赖阻塞需要与代码失败分开报告。

### 6.2 手工验收

1. 在 Docker 沙箱运行状态下打开“进入终端”，确认欢迎卡位于命令输入区之前。
2. 确认容器短 ID、`/workspace` 和当前提示符可见。
3. 确认同步、运行资源、只读文档、临时内容、停止/回收/重启说明均可读，且颜色不是唯一识别方式。
4. 执行 `pwd`、`ls -la`，确认普通命令输出样式和历史命令没有回归。
5. 点击清屏，确认当前内容被清除；关闭并再次打开终端，确认欢迎卡再次出现。
6. 重启或停止容器后，由用户在控制台验证 `/workspace` 文件仍保留；不以本地模拟替代真实 Docker 生命周期验收。

## 7. 非目标

- 不改变 Docker 沙箱权限、挂载模式、工作区路径映射和容器回收策略。
- 不将欢迎语改造成后端动态配置或管理员编辑页面。
- 不在欢迎语中暴露宿主机绝对路径、Docker daemon 地址、平台容器 `/app/data` 物理映射或敏感环境变量。
- 不把“能力越大，责任越大”扩展为阻断式确认弹窗；本次只做常驻的通用风险提示。
