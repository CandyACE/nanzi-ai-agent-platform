# AI 固化报表编辑器统一设计

## 背景

AI 侧“固化 SQL 报表”的编辑弹窗与数据门户手动新建弹窗使用了两套界面和保存逻辑。AI 侧只能编辑少量文本字段，缺少数据源、SQL 试跑、动态参数配置及结果预览；手动入口已经具备这些能力，导致用户在不同入口看到的配置能力不一致，也容易产生校验和权限行为差异。

## 目标

1. AI 新建固化报表、AI 编辑固化报表、数据门户手动新建/编辑统一使用同一个编辑器。
2. 统一数据源、SQL、动态参数、试跑、权限校验、保存和错误提示行为。
3. 保留 AI 场景的上下文信息，让用户知道报表由哪条提问沉淀而来。
4. 不改变固定报表的运行、订阅、分享、个人中心及运行后 AI 分析链路。

## 方案

### 组件复用

以 `DataPortalReportCreateModal.vue` 作为唯一编辑器。AI 入口不再渲染 `SavedReportEditorModal.vue`，而是向公共编辑器传入当前报表或 AI 草稿。

公共编辑器增加以下可选能力：

- 接收 AI 草稿并初始化名称、描述、标签、数据源、SQL、参数配置和默认值。
- 接收编辑态报表 ID，保存时走统一更新流程；无 ID 时走统一创建流程。
- 在存在 `original_query` 时展示“来源提问”只读区；该字段仅用于上下文展示，不拼接进 SQL，也不作为用户可执行内容。
- 支持 AI 入口传入的覆盖层 class/style，兼容嵌入式 ChatBI 和调试页的展示位置。

### 用户流程

1. AI 生成或编辑报表时打开公共编辑器。
2. 系统预填 AI 已识别的报表名称、描述、标签、数据源、SQL 和动态参数。
3. 用户可以像手动新建一样修改数据源、SQL、参数和说明。
4. 点击“试跑测试 SQL”后，由后端执行数据源权限预检、只读 SQL 校验、参数校验和查询；通过后展示结果预览。
5. 只有试跑成功且必填项合法时允许保存。
6. 保存成功后关闭编辑器，刷新固定报表列表；运行路径保持现有行为。

当 SQL 包含日期、月份或自定义参数时，点击“试跑测试 SQL”先打开“试跑参数”弹窗，复用正式运行报表的日期/月份选项、日期输入框和自定义参数控件；用户确认参数后才渲染 SQL、执行权限预检和查询。静态 SQL 仍直接试跑。试跑参数只用于本次预览，不会覆盖报表保存的默认运行参数。

### 权限与安全

- AI 入口和手动入口都使用现有 `preview-sql` 权限预检，不绕过用户数据源权限。
- 继续限制为只读 SELECT 查询，禁止 DDL/DML。
- 动态参数继续使用后端参数化和类型校验，不通过字符串拼接放大 SQL 注入风险。
- 来源提问为只读展示字段，不参与查询执行。

### 兼容性

- 保留已有报表的 `sql_template`、`params_schema`、`default_params`、`dataset_id`、标签和说明。
- 对没有数据集 ID、只有物理数据源名称的 AI 报表，编辑器通过数据源名称匹配已有物理数据源选项；匹配不到时保留原名称并提示用户重新选择。
- 不调整固定报表运行 API、个人中心入口及报表列表筛选语义。

## 验证范围

- 前端契约测试：AI 新建和编辑入口均使用公共编辑器；公共编辑器支持 AI 草稿、来源提问和统一保存事件。
- `vue-tsc --noEmit`。
- 固定报表相关前端契约测试和后端测试。
- 相关文件 `git diff --check`。
- 不启动项目服务，不执行真实数据源查询；真实页面试跑由用户在控制台启动服务后验收。

## 不做的事情

- 不在固定报表核心查询中引入 AI。
- 不修改报表运行时的自动分析策略。
- 不把来源提问自动改写成 SQL。
- 不改变已有报表的权限模型和分享范围。
