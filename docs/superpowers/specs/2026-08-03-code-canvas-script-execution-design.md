# 代码画布脚本运行设计

## 目标

为聊天中由 AI 生成的 Python、Shell 脚本代码块增加“运行”能力。用户在当前代码画布中点击运行，经过明确确认后，在当前会话的安全工作区执行代码，并在画布中实时看到标准输出、标准错误、退出状态和超时/拦截结果。

本期只运行当前 AI 生成的代码块，不运行工作区原文件；工作区文件仍保持现有的查看、编辑和保存行为。

## 已确认的产品决策

- 支持范围：当前 AI 生成的代码块。
- 首期语言：Python（`python`、`python3`）和 Shell（`shell`、`sh`、`bash`）。其他语言继续只展示代码。
- 每次运行：必须先弹出确认框，用户确认后才创建进程。
- 输出：实时显示 stdout/stderr。
- 布局：代码区在上，实时输出区在下；不使用代码/输出 Tab 切换。
- 停止：运行中提供“停止”按钮，立即终止当前执行进程组。
- 默认超时：60 秒；超时后自动终止并显示“执行超时”。
- 输出上限：沿用现有执行边界，最多保留 100KB，超过后明确显示已截断。
- 不自动执行：打开画布或切换代码时不触发运行。

## 用户流程

1. `MessageRenderer` 将长 Python/Shell 代码识别为 `canvas_code` 卡片。
2. 卡片进入画布后显示语言、代码、复制/下载操作和“运行”按钮。
3. 用户点击“运行”，打开确认对话框。确认框展示语言、代码标题、执行目录为“当前会话沙箱”，并提示会产生真实命令执行。
4. 用户取消时不创建后端任务；用户确认后进入 `starting` 状态。
5. 前端建立 SSE 执行流，按事件追加输出；运行中按钮切换为“停止”。
6. 执行完成后显示成功/失败、退出码和耗时；停止、超时、权限拒绝、安全拦截分别显示明确状态。
7. 同一画布再次点击运行时清空上一轮输出并创建新的执行实例；不复用旧进程。

## 架构

### 前端

`MessageRenderer.vue` 的 `canvas_code` payload 增加语言字段，直接生成的 AI 代码标记为可运行；工作区打开的代码不自动获得运行能力。

`ChatCanvas.vue` 增加最小运行状态机：

```text
idle -> confirming -> starting -> running -> succeeded
                                      -> failed
                                      -> stopped
                                      -> timed_out
                                      -> blocked
```

画布新增上方代码区和下方输出区。输出行携带 `stream`（stdout/stderr）、文本和时间顺序；stderr 使用独立的错误视觉样式，但不改变原始输出顺序。运行按钮在 `running` 状态下变为停止按钮，组件关闭、会话切换或执行结束时关闭 SSE 并清理本地状态。

EmbedChat 和 AgentDebug 继续复用同一个 `ChatCanvas`，不在两个页面各自实现运行逻辑。

### 后端 API

新增受 API Key 保护的 SSE 接口：

```text
POST /api/v1/chat/code-executions/stream
```

请求字段：

```json
{
  "language": "python",
  "code": "print('hello')",
  "conversation_id": "当前会话 ID"
}
```

服务端从认证用户和会话 ID 解析当前会话工作区，不接受前端传入任意 cwd、绝对脚本路径或解释器路径。代码写入会话工作区内的临时脚本文件，执行完成后删除临时文件；代码产生的相对路径读写只能落在会话工作区可用范围内。

SSE 事件至少包括：

- `started`：execution_id、语言、开始时间；
- `output`：stream、chunk、序号；
- `finished`：status、exit_code、elapsed_ms、truncated；
- `error`：稳定的错误类型和用户可读消息；
- `stopped`：用户主动停止；
- `timeout`：60 秒超时终止。

另设停止接口，使用 execution_id：

```text
POST /api/v1/chat/code-executions/{execution_id}/stop
```

停止接口必须校验执行实例属于当前用户和当前会话，不能停止其他用户的进程。

## 安全设计

### 共享策略

不要从前端接口直接调用现有 `exec_command` 工具，也不要复制一套新的危险命令正则。将以下能力抽成共享的受控执行服务，由现有智能体工具和新 API 共同调用：

- Shell 删除策略（deny/ask/pass）；
- 用户/角色 `forbidden_tools` 和 `forbidden_commands`；
- 高危命令拦截；
- 工作目录和会话路径约束；
- 超时、输出上限和进程组清理；
- 执行审计事件。

前端确认只表示用户确认本次执行，不能绕过后端权限、黑名单、安全策略或部署级进程隔离。策略拒绝和需要更高权限的情况必须在输出区显示原因，不能伪装成普通脚本错误。

### 进程与解释器

- Python 使用服务端固定解释器并开启非缓冲输出，避免 `print` 长时间滞留在缓冲区。
- `sh` 使用 POSIX shell；`bash` 使用服务端允许的 Bash；`shell` 默认按 Bash 处理并在环境不支持时返回明确错误。
- 每个执行实例使用独立进程组；停止和超时必须终止进程组，而不是只杀父进程。
- 执行必须运行在部署提供的会话/容器沙箱中。若部署环境没有足够的 OS 级进程、文件和网络隔离，功能应通过配置禁用，而不是仅依赖字符串黑名单宣称安全。

## 错误与边界

- 空代码或不支持语言：前端不发起请求，直接提示。
- 确认前关闭画布：取消确认，不创建执行。
- SSE 中断：标记为“连接中断”，尽力调用停止接口，并保留已收到的输出。
- 进程返回非零：显示“执行失败”和退出码，不把 stderr 当成成功结果。
- stdout/stderr 超限：停止继续累积，显示截断标记，并等待进程结束或按策略终止。
- 60 秒超时：终止进程组，显示“执行超时（60 秒）”。
- 用户点击停止：显示“已停止”，不显示为成功。
- 并发：同一画布默认只允许一个活动执行；新运行前要求旧执行已结束或用户先停止。

## 测试与验收

### 后端

- 请求 schema 只接受允许的语言，拒绝任意解释器和 cwd。
- 未认证、错误用户、错误会话不能执行或停止任务。
- Python stdout 实时事件、stderr 事件、退出码和非零失败状态正确。
- Shell 多行、管道和常见命令组合正确传递，不被错误拆分。
- 60 秒超时会清理整个进程组。
- 用户停止会清理整个进程组，重复停止幂等。
- 危险命令、黑名单命令和越权路径均在执行前拦截。
- 输出上限、SSE 断开和并发执行边界有回归测试。

### 前端

- Python/Shell 代码卡片显示“运行”，其他语言不显示。
- 运行前确认框可取消，取消不产生请求。
- 代码区在上、输出区在下，stdout/stderr 按事件顺序追加。
- 运行、停止、成功、失败、超时、拦截状态视觉区分明确。
- EmbedChat 与 AgentDebug 使用同一画布行为。
- 工作区原文件打开时不误显示本期运行入口。

### 验收限制

契约测试和单元测试不能代替真实执行验收。最终交付前需要用户手动启动服务，在已登录浏览器中分别验证 Python 成功/失败、Shell 管道、停止和超时；本开发流程不代跑 `./dev.sh`。

## 非本期范围

- 工作区文件的一键运行。
- 代码编辑器级别的断点、终端交互、输入 stdin。
- 长任务队列、断线恢复、历史执行记录。
- 多语言运行时安装和依赖管理。
- 自动放宽权限或跳过确认。
