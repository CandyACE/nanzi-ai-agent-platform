# session_status 提示词引导优化设计

## 目标

让模型明确知道何时主动调用 `session_status` 获取当前会话、客户端、模型、工作区、沙箱策略和后端运行环境信息，同时不改变工具返回结构，也不把该工具调用变成每轮强制行为。

## 现状

`session_status` 已作为系统隐式只读工具注册，工具描述已经覆盖会话、设备、上下文窗口、工作区、文档目录、用户身份、Token 统计和运行环境等查询场景；返回的 `workspace.sandbox_policy` 包含当前生效的沙箱策略。当前全局 Prompt 工具摘要未为该工具提供专门说明，因此模型主要依赖工具 schema 描述理解调用时机。

## 设计

1. 在 `AgentServicePrompts._PLATFORM_TOOL_ONE_LINERS` 增加 `session_status` 条目，说明其返回范围和“信息不确定时调用”的触发条件。
2. 在运行状态相关的动态工具规则中增加 `session_status` 优先级说明：遇到会话、设备、模型上下文、工作区、沙箱策略或运行环境问题时，优先读取真实状态再回答。
3. 明确该工具是只读运行时事实来源，不是权限凭证；真实权限仍由服务端认证、RBAC、当前轮工具门禁和路径/数据授权决定。
4. 增加 Prompt 组装契约测试，验证工具摘要和调用引导只在 `session_status` 出现在本轮工具集合时生效；保留现有工具注册、只读属性和返回结构测试。

## 不在范围内

- 不修改 `session_status` JSON 返回字段。
- 不改变系统隐式工具注册策略。
- 不在每轮自动调用 `session_status`。
- 不向模型暴露密钥、权限凭证或其他未脱敏内部对象。

## 验证

- 运行新增/相关 Prompt 组装测试。
- 运行 `session_status` 工具契约测试。
- 运行 Python 编译检查和 scoped `git diff --check`。
- 不执行 `./dev.sh`、部署脚本或真实生产环境验收。
