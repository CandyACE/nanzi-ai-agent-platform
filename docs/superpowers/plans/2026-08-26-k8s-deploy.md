# K8S 部署资源实施计划

## 目标

在不引入 Helm、不修改应用运行时代码的前提下，为当前 Docker 镜像提供一套可审阅、
可用 `kubectl apply -k` 管理的 Kubernetes 基础部署目录，并记录单副本、多副本和外部
依赖的边界。

## 步骤

1. 创建 `k8s_deploy/` 目录及 `.gitignore`，防止本地真实 Secret 被误提交。
2. 添加命名空间、ConfigMap、Secret 示例、PVC、Deployment、Service 和可选 Ingress。
3. 在 `README.md` 中记录镜像发布、Secret 创建、数据库迁移顺序、PVC 初始化、部署、
   回滚、日志检查以及多副本前置条件。
4. 执行 YAML 解析和 Kustomize 渲染/客户端 dry-run（以本机工具可用性为准）。
5. 检查 git diff 和未跟踪文件，确认没有修改应用代码、迁移 SQL、Docker 文件或真实凭据。

## 验收标准

- `k8s_deploy/kustomization.yaml` 能引用默认资源并渲染出 Namespace、ConfigMap、PVC、
  Deployment 和 Service。
- Secret 只提供占位模板，默认 Kustomize 资源不包含它。
- Deployment 使用镜像 8001 端口、挂载 `/app/data`、引用 ConfigMap/Secret，并配置
  `/health` 探针。
- 默认没有 `hostPath: /var/run/docker.sock`，没有 Helm 模板，也没有数据库迁移 Job。
- 文档明确 MySQL/PostgreSQL、Redis、PVC、Ingress、单副本和多副本的操作边界。
- 静态校验通过；真实集群部署和服务连通性保持未验证状态。
